# AT1 观察者组合引导计划（prompt 层微调，零代码）

> **定位**：给观察者加「组合已有 facts 找交叉」的固定动作——把"组合链发现"从操作员的直觉变成系统的例行动作。**只动 prompt（手册），不动任何代码。**
> **基线**：`594be66`（playwright 批 + 10-13 修复批已推送），268 绿。
> **状态**：**⚠️ 前半已证伪待重构（2026-10-13 晚深挖，见 §7）**——实查证明观察者 r3 审计就已自主拼出组合链（D-009/D-010，双 fact 引证+复算步进），§1 的"观察者没看出来"前提错误；真问题重定位为**组合关系的表达通道**（语义活在 note 文本、图拓扑是死的）。修复方案见 §7.3，§3 原草稿降级为搁置。待用户拍板后按 §7 重构施工。

## 1. 为什么要做（jwzx 实机教训）

10-12 jwzx run 里，图上躺着三条各自成立的 fact：

1. 全库 GUID 是线性计数器（+145 步进，"高熵不可枚举"不成立）
2. `workflowFileDown.do` 匿名可达（附件下载口不吃登录壳）
3. `user_select_ss.jsp` 泄露教师 GUID（编号泄露面）

**三个碎片拼起来 = 匿名任意下载他人附件**（完整攻击链）。但整条链的"拼接"动作发生在**操作员脑子里**——worker 逐个测、观察者逐条审，没有任何一方把它们连起来。

这暴露的架构缺口：**每块碎片都有记录机制，但"碎片之间能组合"没有发现机制**。不做这个，每条组合链都靠人陪跑盯着——半自动；做了，组合发现变成观察者每轮的例行动作——朝全自动闭合一步。

## 1.5 现状盘点：已有条款为什么不够（2026-10-13 讨论澄清）

现有手册**并非空白**（OBSERVER-MANUAL L56）：「**组合洞察**：发现 fact 间可组合成链 → add_edge（note 写组合逻辑）」；接口契约也定义了边的三来源（worker 声明/观察者主动组合/机械 auto_link）。jwzx 实测它没触发（41 节点入图、零组合边），缺口有两层：

1. **被动条款 vs 固定动作**：句式是"发现了 → 画边"，没有"何时去发现"的触发点——观察者逐条审 finding 时这条从未激活。本计划升级为**每轮固定扫描动作**。
2. **边不派活（更要害）**：即使画了边（fact—derived_from—fact），下轮 worker 读图只是"看到两节点有关系"，**没有任何机制派他去验证链**。本计划把产物改为 **add_intent（开方向=可派工项，进待接方向+prompt 渲染）**，边保留作链路记录——主角从"记账"换成"派活"。

## 2. 为什么是 prompt 层、不是代码层

**管道全是现成的，缺的只是"念头"**：

| 环节 | 现状 |
|---|---|
| 观察 | 观察者每轮审计本来就是**通读全图**（无状态全量扫描）——不需要新增阅读动作，只是换个看图角度 |
| 输出 | `add_intent` 开方向（note 写链路）→ 现成操作 |
| 传导 | 下轮 worker 从图接手 + STATE.md「下轮建议」→ 【引导】→ 现成管道 |

**代码层做不成**：「能不能拼」是语义判断——driver 看不出「GUID 可预测」和「匿名下载口」有一腿，机械组合只能把 facts 两两排列（=把图原样再塞一遍，纯噪音）。代码唯一能做的便宜事是列「未被任何方向引用的孤立 fact」当提示——**留作后手**（§6），prompt 先行，跑一两个靶看效果再决定加不加。

## 4. 三个护栏（防副作用）

| 护栏 | 防什么 | 先例 |
|---|---|---|
| **引证必须**（note 引参与组合的 fact/finding id） | 观察者编不存在的东西、链路无据可查 | Stop 引证护栏同款 |
| **每轮 ≤2 条** | 把全图两两组合刷一屏脑洞方向 | G-1「新方向每轮截断 3 条」同思路 |
| **去重**（已有方向覆盖不提） | 同一组合每轮重复提 | 台账"同断言勿重交"同款 |

成本：prompt 增加约百来 token/轮 + 观察者多一点思考；零代码、零新事件、零管道改动。

- 现有 268 全量回归零变化（本改动不碰代码，理论上不可能红，跑一遍兜底确认）。

**效果观察（下次自然跑批时顺带，不专门验）**：观察者轮的判断书里是否出现 add_intent 且 note 带链路引证；组合方向是否被 worker 接手。jwzx 的 GUID×workflowFileDown 三件套是现成考题——续跑 jwzx 时观察者若自主提出这条链，即直接实证。

### 7.2 重新定位的问题与造成原因

**真问题：组合语义活在 note 文本里，图拓扑上是死的**——引用不连边、边无消费者。具体三层：

| # | 问题 | 造成原因 |
|---|---|---|
| P1 | **note 写了依据、ref 没传**（D-009/D-010 孤岛化） | **契约的激励结构使然**：接口契约写「note（必填，须写详细：为什么开/依据/下一步），**note 是 worker 读图时理解方向的唯一上下文**」vs「ref?（可选，来源线索）」——note 三重强调、ref 一句带过。观察者把依据写进 note、跳过 ref，**恰恰是严格服从了契约的字面**。它没有违规，是我们从没说"引用图内记录必须传 ref" |
| P2 | **边在整个系统里没有消费者** | 没有任何代码/渲染走边查询（worker 读 note 正文；渲染层只数边不遍历边）。对观察者：写 note 有收益（worker 真读），传 ref 零收益（没人消费边）——**理性的按激励行事**。旁证：12 条 sources 边来自部分轮次顺手传了 ref，有的传有的不传——"可选项+无强化"的典型一致性漂移。没有消费者的数据会腐烂，这是本批最重要的设计教训 |
| P3 | **等窗口方向标 open 而非 blocked**（D-009 note 写明"退课窗已过等窗口重开"，state 却是 open） | 手册里 set_state 的 blocked 语义（reason=可检验条件）与"等外部条件"场景恰好匹配，但没有任何地方把两者连起来教给观察者——又一个散落条款无触发点的案例 |

**顺带修正对"链没跑完"的解释**（取代 §1 的错误归因）：①主因=外部条件不满足——观察者判定铸造本人工作流实例的所有路径当轮全关（退课窗 09-20~10-10 已过/反馈提交服务端门/相关端点 404），链的前置 oracle 拿不到，留 open 等窗口是正确工程判断；②次因=run 被操作员提前收尾（wrap-up hint + 手动 stop），worker 未轮到接手；③渲染无重点——兜底 STATE 把 11 个 open 方向平铺，组合链无优先级信号（P3 加重了这一点：blocked 单列后 open 列表本来会更干净）。

## 8. 图现状盘点（2026-10-13 晚问答实录——后续图重构的基线参考）

### 8.1 F-A 的静态代码到底起什么作用——散文→结构的翻译器

**问**：F-A 这部分静态代码起到的作用是什么？

**答**：观察者**已经**在 note 里自然地写引用了（jwzx 证据：D-009 note 里就写着"依据 facts/guid-counter-structure.md + …"）。F-A 不改变任何人的行为，只在这段文字落图时由代码做四步：

```
扫 note 正文 → 找到 "facts/xxx.md" / "findings/xxx.md" 引用 →
查图里哪个节点的 evidence 字段指向该文件 → 补一条 sources 边（已存在则跳过=幂等）
```

作用三句话：

1. **把语义变结构**：note 里的引用是给人读的散文；边是给机器读的结构（可遍历、可统计、可渲染）。F-A 是散文→结构的确定性翻译。
2. **行为无关的根治**：不管观察者传不传 ref，只要它像 jwzx 那样把依据写清楚（它本来就会写），边就自动长出来。AT1 一贯分工哲学——**模型管语义（写清楚依据），代码管结构（把依据变成边）**，与"worker 自由写文件 → 目录页机械盘点"同款。
3. **给 F-B 供料**：F-B（STATE 渲染依据链）消费的就是这些边——没有 F-A，F-B 无米下锅。

### 8.2 现在的图长什么样——一组群岛，不是一张网

**问**：我们现在的图是什么样子？按预设的样子了吗？起到共享图的作用了吗？

**答**（jwzx 终图结构实测，2026-10-13）：

| 指标 | 数值 | 解读 |
|---|---|---|
| 节点 | 41 = 27 fact + 14 intent + 0 finding | finding 空是靶子防得好的正常结果 |
| 边 | **19 条**（sources 12 / yields 4 / supersedes 3） | 全部来自 add_intent 的 ref 参数机械连线；**六动词只用了三个**（spawns / derived_from / 链边零使用） |
| 孤立节点 | **15 个（37%）** | 含 D-009/D-010 两条金子链方向 |
| fact 被边触及率 | 16/27 从未被任何边碰过 | 引用关系活在 note 散文里 |
| 连通分量 | **22 个岛，最大岛仅 5 节点** | 41 节点 22 个岛——群岛形态 |

**按预设的样子了吗**——骨架是，肌肉不是。设计里"图就是阶段""图是唯一记忆"的三个角色，实际兑现：

| 预设角色 | 兑现 | 证据 |
|---|---|---|
| **共享记忆**（worker 轮间接力、防重复） | ✅ 合格 | 每轮 worker 开工读图、r2+ 沿 D-xxx 方向续干没重测、27 条 fact 就是交接介质 |
| **方向看板**（进度账本） | ✅ 合格 | open 11 / blocked 3，STATE 渲染待接方向 |
| **知识图谱**（链路、组合、可检索结构） | ❌ 不及格 | 22 个岛、37% 孤立、组合链只活在 note 散文、**边零消费者** |

**起到共享图的作用了吗**——一半。作为共享**账本**工作得很好；但支撑它的从来不是"图"的部分而是"文本"的部分：worker 读 note 正文、STATE 渲染 note、引导抽取文本。**当前系统所有读取路径都是文本驱动，拓扑层从来不是任何人的食物**——所以拓扑长不出东西，这是群岛形态的真正成因（设计教训与 P2 同源：没有消费者的数据会腐烂）。

F-A/F-B 的准确定位由此而来：**给拓扑层接上第一个消费闭环**——F-A 让结构从既有文本自动长出，F-B 让结构被人看见。落地后图才开始从"带稀疏机械连线的节点清单"变成设计里那张"可以顺着链走的网"。

**后续图重构的基线快照**：节点价值密度高（note 质量是金子，D-009 复算+145/解锁条件分析全在正文里）、拓扑层接近荒地（19 边/41 节点、三个动词、零消费）——重构方向应该是"收割既有语义"而不是"要求生产者改变写法"。
