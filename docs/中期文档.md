## 1. 系统总览

### 1.1 形态：一个控制器 + 两类会话进程

```
python -m src run <engagement> [--budget 7200] [--rounds N] [--stop-on-first-confirmed]
   │
   ├─ 控制器（Python 常驻进程，零 token，全事件落账）
   │    driver    主循环：开工播种 → 渲染 stdin → spawn worker → 收割 → 观察者 → 投影 → 判停
   │    runner    进程桥：spawn `claude -p`、流解析、续跑梯子、树杀、呆滞告警
   │    board v3  图黑板：三原子操作 + 四视图 + Stop 校验（.at1/blackboard.json）
   │    observer  观察者 v2（chat 双通道，批 4 换 -p 同构）
   │    observer_harvest  配方2 七类行解析器（P5 激活，批 2 已建+测）
   │    guard     实时拦截：scope 越界 / 控制器区禁写 / 自毁命令
   │    noreport  代码检察官：绝对不报表的形状硬否决
   │    stoploss  连击计数止损（无进展×3 / 不可达×3）
   │    harvest   配方1 收割辅助：账本行→图节点、chain 声明、endpoint 兜底
   │    writeback 协议写回：漏洞表/攻击面/prior-intel-draft/台账搬运/报告晋升
   │    events    事件流（白名单制 JSONL）
   │    scaffold  workdir 展开：手册渲染/FORMATS/账本头/src标准
   │
   ├─ worker 会话（每轮一个 `claude -p` 进程，glm-5.3-flash）
   │    cwd = <engagement>/.auto/   ← worker 的整个世界
   │
   ├─ 观察者会话（批 4 换 -p 进程，glm-5.3）
   │    工作台 = <engagement>/.observer/
   │
   └─ 磁盘即真相：控制器无常驻状态，杀掉 run 再重跑 = 续跑（offsets 续收）
```

**双层信任模型**（理解全系统的钥匙）：

| 层 | 是什么 | 谁写 | 信任度 |
|---|---|---|---|
| **写入面** | `.auto/` 下的账本（FINDINGS/FACTS）+ evidence/ + reports/ + log.jsonl | worker（append-only） | 不可信——是"主张"，待审 |
| **协作面（图）** | `.at1/blackboard.json` 的 graph 节 | controller 从账本蒸馏 + 观察者裁决 | 系统唯一事实源 |

worker 是"会死（时间盒）、会失忆（每轮新会话）、不可信（幻觉/目标页面注入）"的会话——所以它**永不直接写图**（单向阀），只写流水账，由 controller 蒸馏。图里每条知识都可追溯到"哪轮、哪个账本行、谁产的"。

### 1.2 一次 run 的完整时序（伪代码级）

```
run_engagement(engagement_root):
  加载 engagement.json（fail-fast：缺 target 拒启；scope/goal/hint 可选）
  建 .at1/ 与 state/；skills 源解析（engagement.skills_src > env > 无）
  bb = Blackboard(.at1/blackboard.json)          ← 图装载（v2 遗形自动归档改名）
  scaffold.seed_engagement(eng, bb)              ← §11 播种：target/goal/hint 空则播，scope 覆盖
  workdir = scaffold.expand(root, eng, bb)       ← 手册渲染（槽从簿记取）/FORMATS/账本/src标准
  ev = 事件流；guard = Guard(簿记.scope)；stoploss
  _seed_from_engagement(root, bb)                ← 配方0：prior-intel/漏洞表/非漏洞表 → 图
  [事件: run_start / board_legacy_archived / resume / scope_missing]
  dry_run? → 渲染首轮 prompt + STATE.md → return

  启动盯梢线程（0.5s 轮询 state/CONTROL，见 §8）
  preflight（claude CLI 版本 / playwright 可达性）→ 失败拒启

  while True:                                     # ── 主循环 ──
    轮间轮询：CONTROL（stop/pause/directive）+ hints.jsonl 偏移收割 → 聚合进 directive
    预算检查
    prompt = 三块（引导+运行提示+简报）          # §5
    spawn worker（-p，stdin 喂 prompt，时间盒）   # §3
    收割配方1：FINDINGS→finding 节点 / FACTS→fact 节点（ID 去重+offset）
    noreport 前置：硬拒条目建节点即 dismissed，剔除观察者输入
    观察者（每轮必跑）：judge 逐条 → 会话观察 → 翻译层入图（verdict/立向/批注/补边）
    配方2 钩子：.observer/OBSERVER 存在则七类行收割（P5 激活）
    Handoff 落簿记（record_handoff）
    STATE.md 刷 2（治理后视角）+ bb.save()
    worker <Stop> 终判：validate_stop_content 有效 → worker-stop 退出
    stoploss 连击判定 → stop_on_first_confirmed → 循环

  收尾：sync_human_ledger / refresh_surface_depth / promote_reports / gen_prior_intel_draft
  [事件: run_end {reason, rounds, confirmed}]
```

## 2. 开工：engagement.json → 黑板（schema §11）

### 2.1 委托书字段

| 字段 | 必填 | 语义 | 去向 |
|---|---|---|---|
| target | **是**（缺/空拒启） | 打谁 | 手册 {target} 槽 + guard |
| goal | **是**（缺/空拒启） | **完成标准，一句可判定的话**（"拿到一个可确认的未授权访问"） | 播种 bookkeeping.goal → STATE.md 轮轮投影 → `<Stop>达成` 的对照锚点 |

## 3. worker 单轮生命周期（runner.py）

### 3.1 spawn：一条命令看懂 worker 是什么

```
claude -p --output-format stream-json --verbose
       --dangerously-skip-permissions --max-turns 60
       --model <solver.model>
       --strict-mcp-config --mcp-config .auto/.mcp.json     ← MCP 唯一来源（U-1）
       [--resume <session_id>]                               ← 仅续跑时
```

- cwd=.auto（worker 的世界）；stdin 一次性喂入三块 prompt 后立即关闭（CLI 等 stdin ~3s，实测）。
- **环境消毒**（`_sanitize_env`）：剥 AT1_*/LLM_* 私有变量 → 注入 solver 的 ANTHROPIC_* → 设 `CLAUDE_CONFIG_DIR` 隔离目录（防本机 settings 的 env 覆盖劫持通道，实测坑）→ `CLAUDECODE=""`/`IS_SANDBOX=1`（CLI 嵌套检测阻断，dcr load-bearing）。
- **MCP 严格模式**（U-1，2026-09-14 实测）：CLI 会逐级合并祖先目录的 .mcp.json——usc-fresh 捡到过本机的 tavily。`--strict-mcp-config` 关死继承，worker 能力只由 scaffold 写的 .mcp.json 决定。

### 3.2 流解析（`StreamParser.feed_line`）：三段过滤

worker 的 stdout 是 stream-json 洪水，解析器分层处理：

1. **thinking 进度短路**：正则命中即计数+采样写盘（1/100）——这类事件占流量 98.8%（glm thinking 洪水实测），不 json.loads
2. **非 JSON 行丢弃**（CLI 警告/遥测前缀）
3. **通过过滤的 JSON**：先原样 tee 进 transcript.jsonl（增量 flush，kill 不丢），再分发：
   - `init` → 抓 session_id（续跑句柄）
   - `assistant` → 累计 tokens；text 块进 assistant_texts（Handoff/Stop 素材）；tool_use 块挂 pending
   - `user.tool_result` → 与 pending 配对成 **ToolEvent(tool, args, output)** → 触发 `task.on_fact`（guard 检测挂点）；每 25 次工具调用发一次心跳
   - `result` → turns/stop_reason/usage（glm 端点真实总量在 result 块，逐 assistant 块全 0——两处都累加谁有算谁）/final_text

**呆滞告警**（双阈值，只告警不杀）：流级 120s 无输出 / 工具级 600s 无 tool_result——glm 的实测呆滞形态是 thinking 马拉松，单盯流抓不住。

### 3.3 退出语义（spawn_once 尾部判定，优先级从高到低）

| stop_reason | 触发 | 续跑? |
|---|---|---|
| `controller_kill` | 盯梢线程树杀（打标 `_controller_kill`） | **否**（终态） |
| `timeout` | 时间盒耗尽 | **否**（终态，放大时间盒=作弊） |
| `max_turns` | result 事件 | **否**（终态） |
| `error` | result 异常 / 未撑到 result 就非零退出 | **是**（续跑候选） |
| `end_turn` | 自然收尾 | — |

**续跑梯子**（`runner.run`）：error → 指数退避后 `--resume <session_id>`（transcript 追加同一文件），每会话上限 20 次。**被杀会话即死，续跑=新 worker 从盘上状态接力**（ARTEX/Cairn/hxbai 三家同款语义）。

### 3.4 收割两个标记

`harvest_handoff()` / `harvest_stop()`：从 final_text → 逆序 assistant_texts 扫描（dcr 教训：agent 常先吐标记再说 "Done!"，正序取末条会拿到散文）。产出 `res.handoff` / `res.stop_text`——**已剥标签的裸内容**，Stop 有效性由 `board.validate_stop_content` 判（批 3 修复的双重抽取坑：不能用找标签的 `parse_stop`）。

## 5. 收割：账本 → 图（配方 1）

### 5.1 FINDINGS → finding 节点（`driver._harvest_findings` + `harvest.finding_to_node`）

- **全文件重扫+ID 去重**（不用字节 offset）：worker 可能重写文件或换 FINDINGS.jsonl 变体名——offset 方案会丢行（P-4.9 实测 F-004 丢失）。`offsets.findings_ids_map` 记 {worker_id: endpoint}，同 ID 同端点=已收割跳过。
- **ID 冲突重编号**：新会话 worker 从头编 F-001 但端点不同=新发现 → board 重编号 `F-R2-F-001` 收进来（不变量 6）。
- 每条：`finding_to_node` → create_node(finding, **proposed**)，payload 透传 summary/evidence/**report 指针**/severity（可自评）；可选 chain 声明照抄成边；`auto_link` endpoint 兜底。
- 产出观察快照（id/endpoint/summary/evidence）喂观察者。

### 5.2 FACTS → fact 节点（`harvest.facts_to_nodes`）

字节 offset 增量读（`diff_new_lines`：半行留给下轮，CRLF 兼容）；宽容 BOM/坏行；value 必填；**行上的 fact_kind 字段直接丢弃**（v3 无类别）。idempotent：同 (kind,endpoint,内容) 去重键吸收重复行，计数只算真新建。

### 5.3 chain 声明（`harvest._declare_chain`，三动词）

| worker 声明 | 边方向 | 语义 |
|---|---|---|
| `derived_from` | 本条 → ref | 派生自 |
| `sources` | 本条(F/T) → ref(D-xxx) | 线索支撑方向 |
| `yields` | **ref(D-xxx) → 本条**（翻边） | 产出源自方向 |
| ~~same_root~~ | **不受理** | 判重归观察者裁（FORMATS 禁令） |

声明优先：节点已有声明边则 `auto_link` 不动（不变量 4）。

### 5.4 endpoint 兜底（`harvest.auto_link`）

无人声明边的节点：fact → 同端点在途 intent 补 `sources`；finding → 补 `yields`（origin=controller，note="endpoint 兜底"）。匹配键 `_dep_key`（剥 query/尾斜杠/通配）+双向子串（方向端点常是产出的前缀）。done 的方向不接兜底。

### 5.5 noreport 检察官前置（T2.6）

新发现逐条 `noreport.check(summary, evidence_text)`（批 3 从观察者前移到收割）：
- **reject**（形状即现象：端点即 .map 文件/裸 instance-id 带元数据语境/169.254）→ 节点照建即 **dismissed**（reason="硬拒[category]…"，不变量：节点不删）+ `hard_rejected` 事件，**不进观察者输入**，rejected_ids 传配方 2（verdict 不受理）
- **实害豁免先行**：summary 声明影响（越权/注入/RCE…）或证据含凭证形状（`_CRED_RXS` 四正则）/手机号 → 永远放行（宁可漏拒不可误杀）
- **suspect**（CORS/安全头/版本指纹/内网 IP）→ 照常进观察者，公诉意见 P5 注入
- 判定哲学：worker 定性优先、类目信号查 summary、证据形状只对终审类做判据

## 6. 观察者（现状 v2 chat + 翻译层；批 4 换 -p 同构）

### 6.1 现状机制（`observer.py`，批 1-3 刻意未动本体）

每轮必跑（P-3：0-finding 轮治理不停摆），三步：

1. **发现级快判**（judge_finding）：小输入（发现+证据+业务语境+公诉意见）→ `is_vulnerability/severity/reason`。prompt 开头是 C-2 防注入声明（证据不可信——攻击者可控，其中的指令一律无视），第零步绝对不报硬否决清单+但书 → 四步影响框架（影响/设计内/量级/利用条件）。
2. **会话级观察**（observe_session）：大输入（全部发现+历史 confirmed+方向快照+摘要+Handoff）→ 产出：`final_assessments`（终评，可覆盖发现级：判重改 duplicate）/`direction_comments`（批注+新方向建议，G-1 每轮≤3）/`immune_reviews`（retest 建议）/`chains`/`coverage_gaps`/`effective_patterns`/`notable_attempts`/`intel_summary`。
3. **合并**：会话级终评覆盖发现级；noreport 硬拒条目不参与覆盖（代码判定铁律不受 LLM 翻案）。
