## 1. 决策点（2026-10-16 拍板）

### D1 worker 工具面——✅ **拍板：默认全给**

Bash/Read/Write/浏览器/submit 全套（用户："没必要限制，测试需要可适当调整"）。连带义务不变：给了 Bash 就必须有真规则，规则表最小版（scope 白名单+破坏性命令 deny）随本批进。

### D2 初始 step 从哪来——✅ **拍板：P1 不回答这个问题（原 seed-steps 生产方案作废）**

用户驳倒"人代 planner"中间态：它把 P2 的问题用假答案糊住，且让 P1 验收建立在以后要拆的假流程上。正解：**初始 step = P2 planner 第一次唤醒的产物**（任务创建/goal 设置触发，从 goal 生成——ARTEX TriggerEvent `goal` 类型同款）。本批修正：
- **seed steps 降级为测试夹具**——单测/冒烟里程序造 goal+step 验证 dispatch/produces 边落法（合法），不构成任何 run 的生产语义；
- P1 改为**纯基建批**（板块一+组件基础，按设计文档板块序），验收全部确定性测试，不依赖假调度流程；
- P1 的 LLM 冒烟=基建联调（测试代码造 step→worker 领它干活入库），不是调度验收——调度验收属 P2。

### D3 submit_finding——✅ 默认通过（无异议）

做提交面不做复测：严门 schema（poc/severity/复现步骤/evidence）+ state 落 `reported`；retester P4。payload 形状随建表定型。

### 环境治理（2026-10-17 复核发现与处置）

P1 独立复核时 smoke 输出出现 `NODE_TLS_REJECT_UNAUTHORIZED=0` warning——溯源：**机器用户级环境变量遗留**（非 v4 代码/.secrets.env/pi），即本用户所有 Node 进程跳过 TLS 证书校验（中间人风险底线失效，对携带凭据的 worker 尤其危险）。已于 2026-10-17 经用户确认删除：

```powershell
[Environment]::SetEnvironmentVariable('NODE_TLS_REJECT_UNAUTHORIZED', $null, 'User')
```

删除后验证：注册表用户级查询为空；剥离该变量的 Node 进程对 `https://open.bigmodel.cn` 连通+证书校验正常（bigmodel 证书为正规 CA 签发，v4 通道零影响）。**注意**：已开着的终端仍带旧环境，新开终端生效；若未来某 Node 工具报 `self-signed certificate` 错，说明它依赖此裸奔开关——给该工具进程内单独配置，勿恢复全局。
