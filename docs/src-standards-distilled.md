# SRC 判读标准汇编（四家蒸馏）

> 原料：`src标准/{阿里云,菜鸟,小米,美团}.txt`（原文保留，勿删）。
> 用途：门 2 CLASS_REQS 判定树的权威素材 + 考题来源。本文件是蒸馏版，标注出处。
> 蒸馏原则：跨厂商共识 → 硬规则；单厂商特有 → 标注来源按需采用。

## 0. 跨厂商硬共识（四家全部出现 → 直接进绝对不报）

- Self-XSS / 仅本地解析的 XSS（PDF XSS 等）
- 无敏感操作的 CSRF（收藏、加购物车、一般资料修改）
- 内网 IP / 域名 / 路径 / 版本信息泄漏
- 纯属猜测、无法重现、无意义扫描报告
- 账户枚举、未达标短信/邮件轰炸
- 不涉及安全的产品 Bug（乱码/样式/兼容性）

## 1. 敏感数据分级（菜鸟§六 + 小米§数据定义 + 美团§十二章）

| 级 | 内容（三元组=任意三字段组合） | 出处 |
|---|---|---|
| **极度** | 法定证件无水印照、核心账号密码对、生物识别 | 菜鸟 |
| **重要** | 姓名+手机+地址+银行卡等 ≥3 元组；AK/SK 对、核心服务器/DB 账密；订单三元组（买家姓名/手机/地址/商品/价格） | 菜鸟/小米/美团 |
| **次重要** | 账号名/邮箱/生日/性别 ≥3 元组；非核心业务订单信息 | 菜鸟 |
| **其他** | 设备信息、会员等级、地域、仓储物流类 | 菜鸟（可低收或驳回） |

**量级门槛**：巨量>10万 / 大量>1万 / 少量>1000（小米）；美团越权高危门槛 = **≥3 字段+含 1 个人标识 + ≥5000 条**，字段不足或量不足 → 降中危。

## 2. 分类判读边界（→ CLASS_REQS 素材）

**越权读（idor_read）**
- 收：越权获取用户/商户敏感信息（字段组合+量级定档）；越权查询订单号等业务数据 = 中危（美团）
- 拒：**无敏感信息的越权访问**（美团无效区）；影响用户量极小的降级（菜鸟§五3）

**越权写（idor_write）**
- 高：无前置条件的水平越权敏感操作——改重要信息、订单敏感操作（美团）
- 低：不涉核心数据或少量非重要信息的增删改（阿里低4/菜鸟低4）

**垂直越权（authbypass）**
- 管理功能垂直越权 = **低**（阿里/菜鸟）；垂直越权敏感操作 = 中（美团）——按操作敏感性分档

**信息泄露（infoleak）**
- 高：AK/SK、账密对、可直接连接的核心服务凭据（三家一致）
- 低：phpinfo/SVN/调试信息/仅库名字段名的本地注入（小米低/阿里低）
- 无效：路径/内网 IP/无意义报错（共识）——**本框架更严：非凭证类一律不收（铁律）**

**SQL 注入（sqli_error/diff）**
- 严重：核心 DB、海量敏感多元组（阿里/小米）
- 中：非核心 DB、少量或无重要数据（阿里中2）
- 接 WAF 的须证明可注出 1 条实际数据，仅理论可行 = 无效（菜鸟§五7/10）
- 时间型须排除抖动（差异归因，小米中危"无回显且无法证明实际危害的 ssrf"同思路）

**SSRF（ssrf）**
- 高：可达核心网络并完全回显/图片回显（阿里高3）；支持多协议可探测内网（小米高）
- 中：无回显但能直接访问内网（美团中）
- **无效：仅 dnslog 回连、无任何内网信息**（小米忽略区原文）；内网完全过滤同理（本框架铁律）
- 小米提供官方验证平台 ssrf.dun.mi.com（oob 形态实证）

**XXE / LFI**
- 高：读到敏感文件 / 外带成功
- 低/拒：任意文件读但仅非敏感文件且无法进一步利用（阿里中3）；公开静态文件不算

**XSS**
- 高：核心页面（首页/商品/门店）无交互存储型；影响客服/管理员可获取数据（阿里/美团）
- 中：一般页面存储型；不受浏览器策略限制的 DOMXSS（小米）
- 低：反射型（各家低）
- 无效：self、PDF XSS、小众浏览器限定（共识+小米）
- **投递链是分档核心**：受害者可触达 + 输出点可执行

**业务逻辑/竞争（logic_race）**
- 收：条件竞争、优惠券使用限制绕过、认证流程绕过（美团中）
- **不收：拉新活动、无法实际套现的优惠券**（阿里严重1/高1原文）；纯用户猜测
- 量级：可无限重复刷取→高；大金额少量或小金额大量→中（阿里中1）

## 3. 去重与合并（菜鸟§四 → distinct_from 的厂商实证）

- 同一功能越权增删改查只确认 1 个；相似接口（getDetail/getList）只收 1 个
- 同一根因（同一过滤函数/框架层）只收第 1 个
- 同库 SQL 注入收前 3，第 1 正常后 2 降级
- 0day 按实际业务影响确认，无实际影响案例不收

## 4. 证据要求（美团§6.1 + 小米§4.2.3 → evidence 四段模板实证）

- JS fuzz 出的 API 越权须提供**接口提取、请求构造、遍历过程**完整证明，否则降级（美团）
- 报告须含数据包（raw）+清晰截图；缺 POC = 无效（菜鸟§五7："仅提供利用结果未提供 POC 的，漏洞无效"）

## 5. 大模型产品收录规则（小米§4.2.4 + 美团§7）——LLM 平台类目标专用

**不收**：jailbreak/越狱、prompt leak、模型输出违规内容、模型幻觉类（诱导模拟终端）、沙箱内代码执行（属产品预期功能）、非隐私数据泄露类 AI 风险

**收**：拿到训练数据/敏感配置、越权访问他人对话内容、RCE/沙箱逃逸到宿主机、插件工具漏洞致数据窃取、全量用户服务中断；沙箱执行若能逃逸/穿透内网（可借 SSRF 验证）→ 正常收
