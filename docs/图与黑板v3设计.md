## 〇、架构总纲:两层分家(已定)

| 层 | 是什么 | 谁写 |
|---|---|---|
| **黑板 = 写入面(日志)** | 三账本 + log.jsonl + transcript + auto-log + **reports\**(发现报告),append-only | **worker 只写这一层**,永远只写这层 |
| **图 = 协作面(共享状态板)** | nodes + edges,渗透知识的唯一事实源 | controller 从日志蒸馏(记录员角色)+ 观察者(语义判断)+ worker 声明 |

- worker 写日志 → controller 蒸馏成图 → 一切消费(STATE.md/观察者/控制器/未来 M5)读图。worker 永不直接写图。
- **写入面的最大意义**:worker 本质是"会死(时间盒/预算/被杀)、会失忆(每轮新会话)、不可信(幻觉/注入)"的会话;写入面是把这三者**唯一**转换成系统永久状态的机制。实证:F-001 被杀轮补收割判真、三轮 Shiro 接力。
- **基建边界(已定)**:不上 SQL/服务器。SQL 三触发条件挂起(真并行 / M5 出现文件扫不动的查询 / 图规模爆量);存储保持文件。

**v2 病根**(实测结论):图只是黑板 chains 字段的别名(名实分离);facts 主体不可连边(图覆盖 <10% 知识);边要求"有人判断该写"而无人写(写入端枯竭);观察者被塞 2000 字快照而非自己读图(P-13 静默空输出)。四条互相咬合。

## 一、图:节点(已定)

单节点表,三种 kind,**facts 获得图身份**(旧规则"事实无 id 不可连边"废除)。

```json
{
  "id": "D-001",                     // 类型前缀:D=方向(intent) / F=发现(finding) / T=事实(fact)
  "kind": "intent",
  "state": "in_progress",
  "payload": { ...kind 专属字段... },
  "endpoint": "172.20.9.26:9098",    // 锚定字段,一等公民(无端点标 "global")
  "origin": "worker",                // worker / controller / observer / user
  "round": 3,
  "updated_at": "..."
}
```

| kind | payload 要点 | 状态机 |
|---|---|---|
| intent | goal / note / **comment(观察者批注)** / blocked_reason | open → in_progress → **done / blocked** |
| finding | summary / **report** / evidence / severity / reason | proposed → **confirmed / dismissed** |
| fact | value / evidence(细节指针) | **confirmed / dismissed / superseded** |

- **finding 的定义**:见 §六(发现阶段 = 报告阶段)——finding = 一条被验证的攻击断言,报告是其交付物。
- **superseded 必需**(usc-fresh 案例驱动):4 月情报"1200 Eureka 开放" vs 9 月实测"已关闭"——旧节点不删,标 superseded,`supersedes` 边指向新节点。历史完整,当前态清晰。
- **过期检验已定**:观察者语义质检(读投影时复核关键事实;矛盾走 supersedes,过时无替代走 dismissed+reason)。v2 机械窗口衰减与 confidence 字段退役。
- **fact payload 补 `evidence`**:线索的细节指针(账本行 evidence 透传)。
- 无端点节点(business_context/identity_model)= `endpoint:"global"` 旁挂(不进端点分组,单列"全局认知")。

## 二、图:边(已定,决定权修正版)

**原则:判断权在 worker 声明与观察者手里;controller 是记录员 + 机械兜底。**(2026-09-15 修正:原"controller 蒸馏 90%"的提法把记录量大误当决定权大,用户纠正)

| 动词 | 语义 | **谁决定**(判断) | controller 扮演 |
|---|---|---|---|
| `sources` | 线索支撑方向(依据/弹药) | worker 写线索时声明"指向 D-xxx" / 观察者补线 / controller endpoint 兜底(无人声明时) | **记录员** |
| `yields` | 方向产出了发现/事实 | worker 交产出时声明 / 观察者补判 | **记录员**;无人声明时 endpoint 兜底 |
| `derived_from` | 本节点派生自某节点(因果谱系) | worker 声明优先 / 观察者补非显然者 | **记录员**;同上兜底 |
| `spawns` | 节点催生了新方向 | **观察者/用户** | **记录员** |
| `same_root` | 同根因(**观察者连线时标注正主**,拍板2=B) | **观察者** | **记录员** + 机械 dismiss 非正主者(标注缺失回退先到优先) |
| `supersedes` | 新事实取代旧事实(矛盾检测是语义活) | **观察者** | **记录员** |

controller 独占的纯机械部分:账本行 → 节点(解析+发 id+状态初始化)、冲突重编号、offset 记账——**纯记录,零判断**。

## 三、黑板:存储重构(已定)

**单源单文件**:`.at1\blackboard.json`,两个顶层节:

```json
{
  "graph": { "nodes": [...], "edges": [...] },
  "bookkeeping": { "offsets": {}, "goal": {}, "handoff": "", "config": {}, "intel": [] }
}
```

原则:**graph 节管"我们知道什么、什么和什么有关";bookkeeping 节管"系统记账"**。(字段级契约见 `at1-黑板schema.md` v3.0 §1)

| v2(现) | v3(目标) |
|---|---|
| `_blackboard.json`(知识+记账混一锅) | blackboard.json 两节分立 |
| facts[](无 id) | nodes[kind=fact] |
| findings[] | nodes[kind=finding] |
| directions[] | nodes[kind=intent] |
| immune[](存储) | **删除,变派生视图**:`done 且 yields 为空 的 intent` ∪ `dismissed 的攻击事实` |
| chains[](边库) | edges[] |
| session_intel(观察者输出存储) | **删除**——观察者 agent 产出(OBSERVER)直接收割成节点 comment / 新 intent / 边 |
| ledger.tried/background(分母流水) | **删除**——分母知识不进图,进投影"端点分组"节 |
| verified(影子计数) | **删除**(check_goal 直数 findings) |

**报废清单**:被动抽取四套 kind 正则(_CRED_RXS/_FP_HDR_RX/_KV_RX)、机械窗口衰减——fact_kind 与 confidence 取消后无消费者;过期检验移交观察者语义质检。

**视图全部派生,零存储**:阴性视图(上述公式)/ 端点视图(group by endpoint)/ 谱系视图(每节点 parentsOf + yieldsOf)/ 未测面视图(端点覆盖统计)。

**写入面一行不动**:三账本格式、worker 契约、P-4 的 FACTS 语义教学全部保留(唯 evidence 语义强化:fact 亦必填);**新增 reports\ 目录**(发现报告,见 §六)。

## 四、投影与消费:唯一投影,两个读者(已定)

**STATE.md = 图的唯一投影**。controller 每轮收割后渲染整张图现况:

```markdown
# STATE(图现况)
## 任务概要          ← mission 精要 + 人类已确认发现(status.md 漏洞表)
## 方向谱系          ← 每个方向:状态 + parentsOf(从哪来)+ yieldsOf(产出了什么)
## 阴性视图          ← done 无产出 ∪ dismissed 攻击事实("别再建议这些")
## 端点分组          ← group by endpoint("这个端点上发生过什么")
## 全局认知          ← identity_model / business_context / global 桶事实
## worker 本轮报告    ← Handoff 原文 + 新报告索引(reports\F-xxx.md)
```

- **双读者,各带手册**:worker(执行手册,重点读方向谱系+阴性视图)与观察者(观察手册,重点读发现/谱系连线/报告索引)读**同一份文件**,各自的固定手册写明"重点读哪几节、产出走哪里"。
- **一轮两刷**:收割蒸馏后刷第一版(观察者读它)→ 观察者批注合入后刷第二版(下一轮 worker 读它,含批注)。
- **prompt 摘要 = 路标**:只告诉 worker"图里有什么、去 STATE.md 哪节读"——正文在投影里(P-13 教训:大 prompt 爆思考预算,摘要+按需拉取是实证有效的分层)。
- **不受目录地理影响**:投影从 blackboard.json 渲染,来源唯一(U-1 已关死 .mcp.json 的父目录继承;skills 走 skills_src)——engagement 文件夹建在哪,worker/观察者的世界都一致。

## 五、观察者:整体 agent 化(已定)

**定位:worker 产出的质检员**(审稿人,不是副驾驶)——轮末审查:发现报告的准确性 / 关系对错 / 方向健康 / 整体成色。**产审分离:worker 写报告,观察者审报告——同一个人不能在同一个上下文里既干活又审查自己。**

> **修订(2026-09-18,A17——观察者升格,以下条款被替换/扩展,详见 prompt-全文汇编.md §0.1 A17)**:
> - **定位**:质检员 → **轮间引导者+记账员+实测验证者**。与 worker 同为 -p 进程、**能力同构**(可实测环境、可执行命令),差异只在手册;约束靠手册不靠能力裁剪。
> - **权限矩阵**"工具=Read/Grep,红线=无网络无执行"**作废**——写操作约束等作业纪律由观察手册继承(高危不做等)。
> - **职责③**"方向批注+新方向建议(≤3)"升格为**方向记账权**(没探完挂 intent/卡死标 blocked+可检验条件/瞥见未追立新方向;A11 依赖纪律搬家)+**写下一轮引导 prompt**(主攻+备选次序+自由探索许可,引导非强制)——OBSERVER 契约新增 **guide 行**。
> - **连带**:worker 的 DIRECTIONS 写面退役(收割配方1 对应行删);worker 产出=fact/finding/报告+交接;引导 prompt 成为下一轮 stdin 开场块。
> - **不变**:产审分离(审报告仍归观察者);判停不归观察者(worker 自判 goal 自停+人工+预算);U-5 中途纠偏仍为升级项(轮间引导已是现时钟)。

| | worker | 观察者 |

| 进程 | claude -p(独立进程) | claude -p(**独立进程**,可与 worker 并行——见介入时机) |

### 介入时机(2026-09-15 修正版)

worker 与观察者是**独立进程,可并行**(且分属 bigmodel/DeepSeek 双通道,连 API 额度都不抢)。被堵的只有一件事:**往跑着的 worker 里塞话**(stdin 已关;绕路 = 杀 + `--resume` + directive)。因此两个钟分开:

- **钟 1(观察时机)**:轮末串行(本阶段,变量最少)↔ 并行随工(观察者随 worker 并行,tail 三账本+reports 实时质检,观察延迟归零)
- **钟 2(生效时机)**:轮末交付(本阶段)↔ 中途纠偏(严重问题触发杀/resume/directive)

**本阶段 = 钟 1 串行 + 钟 2 轮末**。钟 1 并行 + 钟 2 中途 = 升级项 **U-5 并行观察+中途纠偏**(中期文档 §11;升级路径平滑:同一个观察者从轮末挪到随工 + 拉警报触发器)。

## 六、发现阶段 = 报告阶段(已定,2026-09-16)

### 6.1 finding 的定义

**finding = 一条被验证的攻击断言**——"攻击者可以做到 X",X 是**成果**,不是动作。

**切分判定问句**(worker 手册教学,一句话):**"这是同一个'我能做到 X'吗?"** 是 → 同一 finding;不是 → 新 finding。

**链完整性检验**(写链报告自问):**"把链中间任何一步删掉,最终断言还成立吗?"** 不成立 → 属于同一条链;成立 → 那是独立的另一个 finding。

### 6.2 粒度判定(实机场景校准)

| 场景 | 断言 | finding |
|---|---|---|
| Registry:`/v2/_catalog` 匿名枚举 + 同次验证匿名拉取 | "我能匿名访问并操作 Registry" | 一个(枚举/拉取是同一断言的影响描述) |
| 只验证了枚举,未验证拉取 | "我能匿名枚举" | **fact**(已验证中间能力,谱系链环);拉取(拿到数据)→finding——09-17 修订,与 worker 手册 A2 三层契约对齐(原判"一个 finding;拉取记为潜在影响") |
| 弱口令进后台 → 越权导出数据 | 登录+导出 | **一个(链式,链报告)**——导出依赖登录,单独登录不构成危害 |
| 9098 同时有弱口令与 Shiro-550(假说) | 两个不同的"X" | 两个(端点相同但断言不同) |
| 同类弱口令出现在 /a 与 /b | 同一个"X"的两个入口 | 一个(same_root 判重已覆盖) |

严重度:**链报告按链的终点定级**(中间环节不单独定级)——与 src标准 链式评级惯例一致。

### 6.3 报告形态与落位

| 断言形态 | 报告类型 | 落位 |
|---|---|---|
| 直接成立 | 单洞报告 | `.auto\reports\F-xxx.md` |
| 多步成立 | **链报告** | `.auto\reports\chain-xxx.md`(每环引用 + 删环检验 + 终点定级) |

**报告结构**(观察手册规定):漏洞描述 / 触发条件 / 攻击动机 / 实际影响 / **业务语境判断(对照 src标准 条款)** / 链路(fact 谱系引用)/ 严重度评级(**引标准原文**)/ 复现要点(引 evidence)。

**落位与晋升**:worker 写 `.auto\reports\`(写入面)→ 观察者审查 → confirmed 的报告由 controller 晋升人工面 `reports\`(给你和 M5);dismissed 的报告留观察者工作台审计。

### 6.4 产审分离(已定原则)

**worker 写报告,观察者审报告**——同一个人不能在同一个上下文里既干活又审查自己。

- worker 的完整论证住在报告里(它最清楚自己怎么打的)
- reason = **观察者的审查意见**(含标准条款依据:"按通用 SRC 标准=高危;业务语境无减损"或"公开可见信息,按 XX 标准 X 条不构成漏洞")
- severity = **观察者按标准核定**(worker 可自评,最终以审查为准——用户经历:worker 把"批量读公开评价"误判高危,公开信息不满足敏感信息字段组合标准)

### 6.5 src标准 判定标准库(已定接入)

- **内容**:五家 SRC 评级细则(小米/美团/腾讯/菜鸟/阿里云:严重/高危/中危分级、数据量级、敏感信息字段组合规则)
- **谁读**:**观察者必读**(审查标尺,按 mission 业务路由一份 + Grep 关键节,不全量读);worker **自愿参照**(写报告定级时)
- **覆盖不到的业务**:退化到通用 SRC 常识 + 四步影响框架(有则参照,无则不拒判)
- **可积累**:新厂商/行业标准 = 往目录加文档,观察者的判定标尺自动升级——判定知识从 prompt 硬编码变成数据资产

### 6.6 观察者的判定方法论(观察手册内置,继承 v2)

第零步绝对不报(硬否决清单)→ 四步影响框架(影响是什么/是否设计内行为/影响量级/利用条件是否归零)→ **src标准 条款对照** → 报告/verdict。判例精神:同一行为在不同业务语境含义不同("能看到手机号"在电商和社交含义不同;"批量读公开评价"不构成越权)。

## 十、参考设计存档(精要)

- **ARTEX**:单节点表(exploration_nodes,六 kind 各状态机)+ 四流程动词边(spawns/yields/proves/derived_from,**工作流副产品系统自动写**)+ frontier 部分索引(认领队列)+ 资产锚定(anchors)+ planner 按谱系渲染喂图(parentsOf/yieldsOf,不塞全量)+ 反噪声条款("0 是合法的但要有正当理由")+ settlement(worker 被杀前 10 轮自行落库)+ Finding 独立表(vulnclass/severity/status triage)+ 常驻后端 PG(基建目的:图活在库里/控制台每页一条查询/认领事务/重启恢复/前端直连)
- **Cairn**:Fact{id,description} / Intent{from:[fact 依赖], to:目标 fact} / Hint;REST 认领-心跳-释放-完结;**Intent 的 from/to 是可执行依赖**;图变化(reason trigger)机械触发规划;worker 经 API 直写图;**fact-fact 无直连——关系经 intent 中介(from 多对多)**
- **hxbai**:死路独立存储(deadends)+ 重复报警(≥2 次同路);可复用产物清单;Fact{kind,value,source,confidence:float,ts,provenance,verified}(float 置信=v2 弃用Reason)
- **RLAgent**:评分器=确定性规则先兜底 + 锚定对比评分(before/after 信息增益)+ 分档细则前置 + 输出单值可降级
