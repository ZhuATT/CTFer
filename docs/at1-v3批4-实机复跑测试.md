## 4. 本轮重点观察项（批4 特有——按优先级）

### 第一层:观察者通道（**零真实运行，本层任何异常都是首发现**）

| 观察点 | 看哪里 | 异常判读 |
|---|---|---|
| 观察者 spawn+跑完 | `state/auto-log.jsonl` 的 `observer_session_end`（应含 tokens/cost/turns） | 无此事件=spawn 失败→看 error |
| 判断书写得合法吗 | `.observer/OBSERVER.json`（五操作+字段）+ `OBSERVER.rejects` | rejects 多=协议难懂→批5 改 |
| submit 行为 | 观察者 transcript 里有没有跑 submit_cmd | 不跑就退=未遵守手册→记批5 |
| resume 反馈链路 | 空产出时 `observer_resume_feedback` 事件→resume 后成功 | exhausted=防线尽了（材料仍在盘上，不丢） |
| guard role=observer | 观察者越界写 `.at1/` → 事件带 `role: observer` | 首跑大概率静默（正常） |
| 模型质量 | deepseek-v4-flash 的判断/措辞质量 | 不够格→切 glm 只改 env（AT1_OBSERVER_PROVIDER=glm） |

### 第二层:worker 新契约

- 开工**第一件事读图本体**（transcript 首个工具调用=Read blackboard.json）
- 写盘=一条一文件（facts//findings//evidence/，格式自由）；判层放对文件夹
- 手册 §2 三层表遵守（成果/中间能力/现象）

### 第三层:图健康度

- 播种只有**画像 1 条**（配方0 修复验证）
- 观察者判断书的操作质量：判层对不对/重复率/组合边有没有真产生
- 图里 proposed 应为 0（状态已消亡）

### 第四层:常规

- worker `<Stop>` 引证护栏（达成引 F-xxx/测尽给理由）
- STATE.md"下轮建议"节 → 下轮【引导】块抽取正常
- 计量收全（worker+observer 双会话 tokens/cost，P4 关闭验证）

## 5. 异常处置原则（热修 vs 记录）

| 异常类型 | 处置 |
|---|---|
| 观察者 spawn 失败/判断书格式错/不 submit | **热修**（通道问题，修完重跑） |
| 观察者判定质量差（误判/漏判/被注入带偏） | **记录案例进批5**，不当场改架构 |
| worker 不守写盘纪律 | 记录（观察者全量扫描兜底不丢），手册措辞后续调 |
| 图节点异常（proposed 出现/重复条目） | 记录+复核，疑似执行器缺陷进批5 |

**首轮数据若因通道问题报废——属预期**（观察者通道零真实运行），热修后重跑即可，不算失败。
