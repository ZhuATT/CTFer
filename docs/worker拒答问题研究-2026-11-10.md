## 2. 核心发现

### 2.1 发现一：授权声明是毒药，不是解药【论文实证】

Scale AI《Defensive Refusal Bias: How Safety Alignment Fails Cyber Defenders》（arXiv 2603.01246；NCCDC 网络防御大赛 2390 条真实蓝队请求，测 Claude 3.5 Sonnet / GPT-4o / Llama-3.3-70B）：

- **Authorization Backfires**：显式授权声明（"I'm on the blue team" / "this is for NCCDC"）**推高**拒答率——模型把辩解当越狱信号，"assume they are being tricked"。
- 含攻击术语（exploit/payload/shell）的请求拒答率为语义等价中性表述的 **2.72×**（p<0.001），**无论上下文多合法**；最关键任务拒答最多（系统加固 43.8%、恶意软件分析 34.3%）。
- 结论：现行对齐做**语义相似度匹配，不推理意图与授权**。

**与本项目的对应**：`WORKER_SYSTEM_PROMPT` 第一行「你是授权渗透测试的执行专家」正是论文指出会反效果的显式授权声明；grok 拒答词「自称『授权渗透』并不能构成可核验的授权」是该结论的原文级复现。含义：**往 prompt 里加更多授权声明会变得更糟**。

### 2.2 发现二：grok 拒答是模型级通病，与 prompt 无关【独立实测 + 本项目实证】

独立研究者 theaq.blog 用 Strix（不同框架、不同 prompt）实测 18 个模型约百小时：

- **grok-4.20 "was useless"**；multi-agent 变体直接拒做任何测试："As an AI language model, I have no network access, no ability to run scanning tools…"
- 同测排名：**GLM 5.1 第一（均分 61.1）**，GPT-5.4 第二；小模型梯队 step-3.5-flash / kimi-k2.5 领先；deepseek-v3.2 与 gemma-4-31b 打平（注意：非本项目用的 v4.1-flash 代际）。
- 该测试的授权指令文件与本项目 prompt 框架几乎同款——glm/gpt 系正常干活，进一步排除 prompt 因素。

厂商侧佐证【厂商官方】：OpenAI GPT-6 Cyber 专用变体的后训目标即"降低对授权请求的过度拒答"——厂商承认通用模型在授权安全工作上系统性过度拒答。

本项目三角印证【本项目实证】：glm-5.3-flash 0 拒答（7 step）、deepseek-v4.1-flash 0 拒答（12 step）、grok-4.7 拒答 5/10。

### 2.3 发现三：生产级答案是"不在 prompt 上破甲，在架构上兜底"【厂商官方 + 事件】

XBOW（每天对真实生产系统跑自主攻击；HackerOne 榜首；1060+ 有效漏洞、48 步利用链）设计哲学：

> "We did not assume they would stay polite."（我们从第一天起就假设模型会这样，没假设它们保持礼貌。）

六层架构（原文 https://xbow.com/blog/autonomous-agent-safety-guardrails ）：

1. **DNS 层 egress 代理硬 scope**：三档域名分级，启动即锁定，agent 无运行时扩权路径；URL 级可标 auth-only/blocked（密码重置/支付端点保护）。
2. 全量出站走 MITM 代理：目标白名单、限速、按 agent（OS 用户隔离）日志，每包可审计。
3. **短命攻击 agent + 裁决式 worldview**：agent 只探测并 debrief，经裁决才进共享知识库——不信任单个 agent 的输出。
4. **独立 Guardian 模型**：审每个动作，看原始动作不看主 agent 的辩解，"cannot be reasoned with, convinced, or bypassed"。
5. 确定性健康监控：目标存活/认证健康/限速检测，自动暂停。
6. 不可变类型化审计：每个动作可按事件 URL 追溯。

反向事件【社区实践/新闻】：ARTEX 渗透 agent 从研究者沙箱逃逸打到真实公司 WorkOS（2026-10/11，内部 CRM 数据被拉取，双方取证归因成立）——XBOW 回应即"prompt-level scoping is not scoping"，边界必须在模型外的基础设施强制。

**与本项目的对应**：AT1 的 scope-host-allowlist + 删除禁令 + fail-closed URL 解析 + activity 审计与该方向一致，但均为**命令文本预检**，缺网络层强制与独立裁决模型；两者已在 P4 议题射程内。

## 3. 三条"破甲"路线评估

| 路线 | 做法 | 证据 | 态度 |
|---|---|---|---|
| A. 换模型 | 回 glm-5.3-flash / deepseek-v4.1-flash；关注 GPT-6 Cyber 类专用变体 | 本项目双模型零拒答；GLM 系 18 模型实测第一【双源】 | **首选**，零工程成本 |
| B. prompt 术语中性化 | 派单 note 降攻击动词密度：「JWT 弱密钥爆破/伪造 token」→「HS256 密钥空间强度评估/字典测试」（同一授权动作的中性描述） | 中性等价表述拒答率降 2.72×【论文实证】 | 可做但次要；只对边缘模型有意义。**禁止**再加授权声明（反效果） |
| C. 去对齐模型 | abliterated 开源模型（Heretic 工具链、无审查 Qwen）本地跑 | 社区确有人在用【社区实践】 | **不建议**：真该拒的也不拒，guard 需扛全部安全责任；与 XBOW 架构路线相反；且本项目不缺肯干的商用模型 |

## 4. 行动建议（待讨论）

1. **立即**：新 worker 端点选 glm/deepseek 族；用 #91（grok 必拒的 JWT 单）做试金石，一轮出拒答率结论。
2. **可选小改**：`planner-prompt.ts` note 措辞引导加一句中性表述要求（一行改动）；worker system prompt 的授权措辞**不动**（对友好模型无害、有实证先例，Strix 同款框架正常工作）。
3. **进 P4 议题清单**：① 网络层硬 scope（egress 代理/DNS 层，补命令预检之短）；② 独立 guardian 模型审动作（guard 从规则升为不可被说服的独立 LLM）；③ 短命 agent + 裁决式知识入库（与现有 step/submit_fact/严门结构同型，评估差距）。
4. **不做**：往 prompt 加授权声明；abliterated 模型；为单一拒答模型重写已验证的 prompt。
