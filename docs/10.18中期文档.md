## 1. 系统总览

### 1.1 形态：单进程调度器 + 两类 LLM 会话（pi L1 in-process）+ 一辆托管浏览器

```
node dist/index.js run <task> [--step-timeout-min N] [--max-rounds N]
   │
   ├─ runTask 调度器（scheduler.ts，常驻本进程，自身零 token）
   │    启动   loadTask → run.lock 抢锁（活拒报 pid / 死接管）→ 清扫 running→exhausted
   │           → initTask（幂等 + seed step + standards/ 快照）
   │    watcher（1.5s tick，双信号源）
   │           control/stop  → stopRequested + abort 当前会话（与超时同一条优雅收尾路）
   │           steer.jsonl   → 新行且目标在跑 → agent.steer() 送达 + steered 事件
   │    循环   终止检查（goal achieved / closed / stop / maxRounds / budget）
   │           → hints 收割 → 有事件（方案 C）或无 open → 唤醒 planner
   │           → worker 领 step（priority desc, id asc）→ step_done/finding 事件累积
   │    收尾   activity 落账 + finally（删自己的锁 / 关库）
   │
   ├─ planner 会话（pi Agent，每次唤醒全新；通道= config.channels.planner）
   │    工具面六：add_step（批量≤4+拒重）/ conclude_task（openCount==0 防线）/
   │             prove_goal（evidence 必须图内 fact）/ TodoWrite / list_facts / node_detail
   │    prompt v1.2（决策流程式：读变动→判目标→判方向→定产出）+ 收官判定变体（空队列三选一必答）
   │    无 Bash（纯读图）；usage 落 activity（worker="planner"，token 四列）
   │
   ├─ worker 会话（pi Agent，每 step 一个；通道= config.channels.worker）
   │    工具面七：Bash / Read / Write / browser_navigate / browser_snapshot /
   │             submit_fact（幂等+证据哈希）/ submit_finding（noreport 前置）
   │    guard = beforeToolCall 拦截式（scope host 白名单 + 破坏性命令禁令）
   │    态势 = 血缘精简版（goal + 本 step 直产 facts + 上游链 produces facts + counts）
   │           + 【standards 索引】（渐进披露：一行一册进 user 首条，正文按需 Read/Grep）
   │    prompt = 6 行系统（含插话纪律句）+ 阴性出口完成定义；thinkingLevel:"low"（glm 坑）
   │
   ├─ browser-pool（P0 直译）：detached Chrome（CDP 随机口）→ .at1/browser.json 记账
   │           → 探活自愈 → 收尾杀树删账；BrowserSession connectOverCDP 附着（只断连不杀进程）
   │
   └─ 磁盘即真相：SQLite graph.db（nodes/edges/activity）+ task 目录（evidence//standards//control/）
       杀进程重跑 = 断点续接（死锁接管 + 尸体清扫 + resume 触发，H4 真机验证）
```

### 1.2 信任模型（v4）

| 主体 | 写什么 | 读什么 | 说明 |
|---|---|---|---|
| worker | 图写入**只能经 submit_fact/submit_finding 工具**（程序校验：证据哈希/幂等/noreport 预检） | 血缘态势 + standards/ + evidence/ | 模型从不直接碰 DB；guard **拦截式**（与 v3 的"只记不拦"刻意不同——L1 钩子天然给拦截点） |
| planner | 图写入只能经 add_step/conclude_task/prove_goal 工具（拒重/D2 防线/空气证据校验） | 全图态势 + todos.json + standards/ | 调度唯一权威；hint 对它是建议级（可采纳/忽略，待补留痕措辞） |
| operator | control/hints.jsonl（调度层插话）/ steer.jsonl（执行层插话）/ stop 文件 | — | 不直接命令 worker（D5）；steer 不影响调度（D11） |
| scheduler | step/goal 状态翻转 + activity 记账 | — | 不产生内容；事件驱动唤醒（方案 C） |

### 1.3 一次 run 的时序（伪代码级）

```
runTask(task):
  抢锁（活锁抛错拒双开 / 死锁覆写接管）
  watcher = 每 1.5s { stop 文件? → abort 当前会话 ; steer 新行? → 送达或丢弃记账 }
  清扫 running→exhausted；initTask（幂等；standards/ 快照）；非 fresh 且图非空 → resume 事件
  clearControl（吃掉历史 stop）
  while true:
    终止检查（五触发器，见 §3.2）
    hints 收割（偏移防重放）
    if 有未消费事件 或 无 open step:
      唤醒 planner（v1.2 + 事件 delta + 态势 + todos [+收官判定变体]）→ 消费事件
      无 open step 且派 0 → planner-zero 判停
    step = 领一条（priority desc, id asc）→ running → runWorkerStep（timeout 与 abortSignal 并联）
    → step_done/finding 事件 → 下轮
  finally: 删自己的锁 / 关库
```

## 2. 图与基底（SQLite）

- **表**：nodes（kind=goal/step/fact/finding + state + payload JSON）/ edges（四关系）/ activity（全程时间线，含 token 四列——验收取证主源）。
- **边 = 账本，状态 = 开关**：`dispatch`（goal→step 谁派的；单 planner 单 goal 今天仅审计价值，为多 worker 留）、`produces`（step→fact/finding）、`proves`（fact→goal/finding 证据血缘）、`derives_from`（上游→新 step 派生依据）。
- **goal 状态机**：`open → achieved`（prove_goal：evidence 必须图内 fact，落 proves 边）/ `open → closed`（conclude_task：openCount==0 防线，**不落边**——收尾不是证明）。reopen = 新 goal + 原图续跑（D9，M5 入口）。
- **拒重三道防线**：程序精确硬拒（归一化=trim+空白折叠+小写，只拦 open/running）→ prompt 语义比对 → 范围限缩。实测：两轮真靶零同义重派。
- **noreport 三态**：reject（.map 端点/instance-id/元数据无凭证——硬拒不入图）/ suspect（CORS/安全头/指纹等——放行+公诉意见）/ pass；实害豁免门先行（summary 声明影响/凭证形状/手机号）。P2fix 接通 endpoint 后 reject 分支激活。

## 3. 调度与介入

### 3.1 唤醒（方案 C 事件驱动，D6）

事件源四类：`step_done / finding / hint / steered`（+续跑 `resume`）。有未消费事件 → 先唤醒 planner 消费再领 step；空事件且有 open → 直接 worker（成本纪律）。**无"新 step 事件"**——step 唯一生产者是 planner 本人。planner-zero 判定保留（唤醒后无 open 且派 0 = 判停）。成本实测：planner 单次唤醒 ≈5k in/3k out，每 step 一次唤醒，整体可接受（用户知情拍板）。

### 3.2 任务结束五触发器

`prove_goal`（达成）/ `conclude_task`（探尽收尾，仅空队列时刻）/ `maxRounds` / `budget` / `control-stop`。收官判定变体（空队列时注入）："三选一必答，0 派不是选项：派真方向 / prove_goal / conclude_task；沉默收场是严重错误。"

### 3.3 操作员介入四通道

| 通道 | 层级 | 语义 | 实测 |
|---|---|---|---|
| hint（CLI/文件） | 调度层 | 建议级——planner 转译为 step，可裁量；时效=当前 step 跑完的下轮唤醒 | ✅ 送达/消费/正确忽略（goal 已达成时不盲从）；**采纳分支欠真机样本** |
| steer（CLI `--step`） | 执行层 | 对在跑 step 补情报/纠偏，不影响调度；watcher 秒级送达；steered 事件进 planner 防盲区 | ✅ 0.6s 送达→worker 吸收→fact #11→成为 goal 唯一 proves 证据 |
| stop（CLI） | 全局急停 | 三层：信号文件 → watcher 秒级 abort（优雅收尾）→ 锁 pid 人工 kill 兜底 | ✅ 5 秒内退出，产出保留 |
| reopen | 目标层 | 新 goal + 原图续跑 + goal_changed 触发 | 预留（M5 UI / P3 CLI） |

## 4. 模型通道（pi L1 微内核）

- **栈**：`@earendil-works/pi-agent-core`（Agent 循环 + steer/abort 原生）+ `@earendil-works/pi-ai`（streamSimple + Model 对象）。无 SDK 层、无 CLI 子进程、无 pi 目录依赖（skills/standards = 我们自己的目录约定）。
- **隔离**：baseUrl 钉在 Model 对象、apiKey 显式传 `getApiKey`——**机器 env 永远够不着**（pi-ai 不读 ANTHROPIC_BASE_URL；env 兜底只在忘传时生效，我们永远显式传）。

## 9. 施工坑档案（v4 累计）

1. **glm-5.3 拒 thinking:disabled（1210）**——报错文案误导，必须 thinkingLevel:"low"
2. **Windows 大小写不敏感**：CONTROL 文件 vs control/ 目录同名冲突（EISDIR）→ stop 落 control/stop
3. **better-sqlite3 占位符计数**：addStep INSERT 5→7→6 两次数错，单测当场抓
4. **手写 YAML 行内对象缩进不感知**：顶层 run: 被塞进 channels: → 重写缩进栈式
5. **noreport 平移笔误**：Python lookbehind 被写成空分支 hack——JS 原生支持，直接平移
6. **中文空格归一化**（P2+P2fix 两次）：空白折叠≠删空格——"测 A"≠"测A"，测试数据别想当然
7. **initStandards 未建目录先拷**：copyFileSync 不建父目录，ENOENT 被静默吞 → 先 mkdir，零拷贝回滚
8. **stepLineageView 漏直产 facts**：被掐会话的产出也是接续上下文 → 补 produces 直取
9. **双开无互斥**（canary 实锤 38 秒重叠）→ run.lock；顺带发现"杀进程没杀干净+重跑"是真实操作模式
10. **runPlanner 吞 LLM 错误**（429 事故）：显示"派 0 条"极具迷惑性，一度误判为模型不收工 → 下批 blocked 透传；**排查此类先直接探针，别先改 prompt**
11. **git-bash 中文 payload 按 GBK 发送**：curl 探针远端 UTF-8 解析报 0xbb——连通性测试用 ASCII
12. **runPlanner acceptedCount 初版**：before/after 计数都在 prompt 后调用恒 0 → 工具闭包计数器
