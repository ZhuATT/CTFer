## 1. 问题登记（P1-P5）

### P1 观察者的边会蒸发 —— 🐛 bug 级，唯一"真坏"的问题

- **现象**：观察者判重顺产的 same_root 边，轮 N+2 起从图上消失。
- **根因**：B4 施工把观察者边存进了 `session_intel.chains`，而 `update_session_intel` 的语义是**每轮整体覆盖**（该语义对原五个会话级字段是合理的，B4 新增的"边"字段撞上了它）——设计冲突，非笔误。
- **影响半径**：图丢边 → 接力有损（worker 下轮看不到上轮关联）→ M5 图不完整；观察者自身跨轮也不记得自己产过什么边（可能重复产）。
- **修复方案**（治理批 #1，已写死）：黑板新增常设 `chains` 一等列表——`add_chains()` 入口 + normalize 校验 + `(rel, frozenset(refs))` 去重 + 持久化；观察者边改走此入口；`_all_chains`/YAML 图层改读常设列表。旧 session_intel.chains 一次性迁移。
- **验证**：4 条测试（跨轮存续/去重/降级/roundtrip）。
- **状态**：✅ 已修（治理批 #1，常设 chains 边库；跨轮存续/去重/迁移 4 测试锚定）。

### P2 provenance/verify_fact 死字段 —— 违反自家原则 2

- **现象**：`verify_fact` 全仓零调用（grep 仅 pycache）；provenance 字段产出后无人消费。
- **根因**：phase3.5 架构转向时，verify_fact 的旧"run 回调重放"语义随四门一起退役，但**字段和新方法签名留下了**，接线从未做——与 conf 当初被处死同病，躲在"v2 接线"名义下。
- **影响半径**：被动事实的 observed 永不被校验（陈旧事实永不降级）；字段死重。
- **修复方案**（治理批 #2，已写死）：轮末对被动抽取类事实做 **transcript 复现抽验**——value 在账本双形态解码文本中不可寻 → observed 降 inferred；凭证 provenance 照旧冻结；prose 结论类跳过；零网络（复用 C-5 hay 基建）。
- **验证**：3 条测试。
- **状态**：✅ 已修（治理批 #2，轮窗复现抽验+对称自愈；施工补强=轮窗记账防整卷空转；5 测试锚定）。

### P3 账本隔离是软的 —— 已知残留，正解在 pi

- **根因**：Windows 原生无容器，dcr-harness 双容器硬隔离的等价物只做到**目录分离 + CLAUDE.md 禁令 + guard 事后检测**——worker 理论上可用绝对路径写 `.at1/transcript.jsonl`。
- **影响半径**：门 3 锚（transcript 对账）的信任假设打折——账本若被污染，C-5 v2 的全部对账归零。概率低（guard_violation 事件会立刻暴露、观察者会看到诡异账目形态），但非零。
- **修复方案**：短期**接受 + 监控**（真实环境把 guard_violation 列为首跑观察项）；正解 = pi 迁移 P5——`tool_call` extension 把 `.at1/**` 禁写升为**引擎内物理拦截**（D2 的新论据）。
- **状态**：✅ 处置已定（接受+监控），无独立动作。

### P4 transcript_check 语义盲区 —— 设计内边界

- **现象**：C-5 v2 后仍防不住"真打过同参数请求 + 响应断章取义"——机械层只见字节，断章取义是语义问题。
- **根因**：信息源不对称是设计本身（账本只对代码说话，不给 LLM）。
- **修复方案**：不修。靠观察者语义判定 + 人审定稿兜底。已记录于 transcript_check docstring。
- **状态**：✅ 关闭（设计内）。

### P5 判官 anchor_note 措辞变更未经真实验证 —— watch 项

- **根因**：C-5 v2 把判官证据段的"已通过验证，内容为真实"（硬编码、部分未中时是说谎）替换为对账摘要如实渲染；毒饵验证体系已停（C-3），行为影响无独立验证。
- **影响半径**：低——新措辞是纯事实陈述且带加权引导，理论上中性偏正。
- **修复方案**：不单独验证。真实环境首跑时把 judge 的 reason 与对账标记对照抽查（watch 项 T5 的子项）。
- **状态**：✅ 转 watch。

## 4. D3 真实环境开工参数（推荐值 + 理由）

| 参数 | 推荐 | 理由 |
|---|---|---|
| `--budget` | **7200**（默认） | F 拍板阶梯 (1200,1200,1800) 下 = 4-5 轮；首跑够观察接力而不过度烧钱（估 $2-4，selftest 基线 $0.247/3-turn） |
| `max_rounds` | **6**（默认） | stoploss 兜底在，轮上限不敏感 |
| `observer_on` | **True** | 观察者是本轮全部新机制（治理三件套/边/批注）的消费中枢——关掉等于白测 T2/T4/T5 |
| `stop_on_first_confirmed` | **False** | A4 实证：confirmed 后下一轮有链式价值（轮 1 SQL → 轮 2 XSS） |
| stoploss | 默认（四维） | 无修改理由 |
| 引擎 | CC（`AT1_ENGINE` 不设） | D2 选 A 的落地 |

**首跑目标选择建议**：选**低价值/非生产/测试环境**目标——本轮首跑身负五项新机制首验（DIRECTIONS/chain/观察者三件套/anchor_note/时间盒），本质是带产出的验收跑，别拿高价值目标当小白鼠。真实高价值目标等首跑报告出来、按 T1-T6 指标校准后再上。

**首跑必看清单**（T1-T6，auto-log 可回放）：worker 首动作接/开新 ｜ DIRECTIONS 格式遵循率 ｜ STATE.md 被读率 ｜ observer 方向忽略率 ｜ guard_violation 有无（P3 监控）｜ 判官 reason vs 对账标记对照（P5）｜ 成本与 429。
