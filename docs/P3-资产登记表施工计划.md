## 1. 全景（目录形态 + 数据流）

```
AT-src/
  projects/
    <名>/assets.db          ← 项目资产图（共享）：assets / asset_tasks / anchors
  tasks/
    <task>/                 ← 探索图原地不动：task.json(+project 字段) + graph.db + evidence/ ...
```

```
建 task：task.json scope.hosts →（程序）find-or-create 资产 + asset_tasks 登记   ← scope 建立
跑 task：worker register_asset 登记侦察发现（客观直录，不受 scope 限）
         worker submit_fact 带 endpoint →（程序）归一化 → find-or-create → 落锚  ← 校验器5
读 图：planner list_assets（WHERE id IN asset_tasks——越界资产存在但不可见）
         graphOverview 增 coverage 块（untouched scope 资产清单）               ← 消费闭环
第二个 task 起跑：find-or-create 命中已有条目（复用，不重新侦察）
                  首轮 user 首条注入【项目简报】（前任 findings+锚定 facts）     ← 续测
扩 权：scope-add → watcher 重载 → guard 放行 + planner 收 scope_changed
```

## 2. 施工卡

### P3-1 assets.ts 基建（中卡，本批地基）

新文件 `src/assets.ts`（风格照 db.ts）：

- `openAssetsDb(path)`：WAL + 三表 DDL：
  ```sql
  assets(id, project_id, type, host, port, url, payload, first_seen_task, created_at)
        -- project_id 单库一项目本冗余，保留是为合库日不破表（§2.6 ④）
        -- type: subdomain|ip|endpoint；url=归一化全形；去重 key=(host,port,url 规范化)
  asset_tasks(asset_id, task_id, origin, created_at, PRIMARY KEY(asset_id, task_id))
        -- origin: operator(建 task 时)|scope-add(扩权)|auto
  anchors(task_id, node_id, asset_id, created_at, PRIMARY KEY(task_id, node_id, asset_id))
        -- node_id 是 task 库内 id 的跨库弱引用（本就"不设外键，应用层管引用"）
  ```
- `normalizeEndpoint(raw)`：URL/host:port 二形归一 → `{host, port, path}`（D5 规则：host 小写、默认端口补齐、去 query/fragment/尾斜杠）；裸 host 当 `host:443` 还是报错？——**接受裸 host**（port null，登记为 subdomain 型）。
- `findOrCreateAsset(db, {project, type, host, port, url, payload, taskName})`：撞 key → 返回旧 id（幂等，**维护=无维护的根**）；miss → INSERT（first_seen_task 记发现者）。
- `registerAsset(...)`：zod 契约（桶四#7 应用层）+ findOrCreateAsset 包装（worker 工具的落点）。
- `resolveScopeHosts(db, taskName, hosts[])`：逐 host find-or-create + asset_tasks 登记（origin=operator）；幂等（已登记跳过）。
- `anchorFact(db, taskName, nodeId, endpoint)`：normalize → find-or-create → INSERT OR IGNORE anchors。
- `listAssetsInScope(db, taskName, {page, q})`：`WHERE id IN (SELECT asset_id FROM asset_tasks WHERE task_id=?)` + 每资产锚计数（**越界资产存在但不可见——id 所有权过滤，不是域名判断**）。
- `coverageQuery(db, taskName)`：scope 资产 LEFT JOIN anchors（限本 task 锚）→ `{scope_total, anchored, untouched[{id,type,host,port,url}]}`（untouched 截 30 行进 prompt）。
- 单测：归一化各形态/幂等/过滤/coverage 计数（夹具直灌）。

## 4. 风险与预案

| # | 风险 | 预案 |
|---|---|---|
| ① | 归一化规则边跑边调（IP:端口/CDN/大小写路径/非标端口） | 夹具单测盖常见形态；canary 暴露再补规则（§9 已预告"施工边跑边调"） |
| ② | anchors 弱引用悬空（task 目录被删/改名后 coverage 计数虚） | 查询一律 LEFT JOIN 容忍悬空；不做级联清理（过程史比图活得久的既有哲学） |
| ③ | 同项目双 task 并跑写 assets.db | WAL+短事务安全；本批不测并发（单 worker 世界），只保证不损 |
| ④ | 简报体积失控（前任 findings 很多） | findings 全量是设计选择（漏报比长更贵）；渲染一行一条，超 20 findings 再议截断 |
| ⑤ | goal 选取改动波及面（currentGoal 替换四处"第一条"） | 全部换 helper+多 goal 单测盖；canary 存量单 goal 行为不变（回归确认） |
| ⑥ | scope.changed 与 worker 启动竞态 | 只增不减语义下最坏=晚一 step 生效；注释写明，不做锁 |
