# 菜鸟网络安全应急响应中心 (ASRC/菜鸟) 漏洞评分标准

> **适用范围**：菜鸟网络各业务线、物流骨干网、仓储系统、快递中台、移动端 APP 及相关云上设施。  
> **体系归属**：阿里巴巴开源安全与应急响应体系 (ASRC) 标准派生版。零信息丢失，纯结构化 Markdown 汇编。

---

# 一、ASRC 敏感数据分级与升降级规则

### 1. 敏感数据四级划分标准

| 级别 | 定义与包含内容 | 组合形态要求 |
| :--- | :--- | :--- |
| **极度敏感** | ① 个人法定证件的无水印清晰照片<br>② 核心账号体系的账号密码对<br>③ 人脸、指纹等生物识别信息 | 单项即可直接成立 |
| **重要敏感** | ① 可直接识别个人的信息：**姓名、手机、地址、银行卡号的三元组或以上数据**<br>② 用户业务身份凭据：AK/SK 密钥对、可直接连接的核心业务服务器/数据库账号密码<br>③ 公司内部数据：员工姓名花名、部门、联系方式、职级的三元组或以上数据<br>④ 核心业务数据：**包含买家姓名/手机/地址/商品/价格的订单三元组或以上数据** | 必须满足指定的三元组或多字段组合 |
| **次重要敏感** | ① 个人基础信息：**用户账号名、邮箱、生日、性别的三元组或以上数据**<br>② 业务轨迹数据：核心电商业务买家商品浏览记录、收藏记录，核心电商之外业务的普通订单信息 | 必须满足三元组要求 |
| **其他数据**<br>*(低级接收/驳回)* | ① 商家公开/一般信息：证照、联系人、联系电话、银行账号、经营地址、营收数据等<br>② 仓储与物流运营数据：物流人员个人信息、车辆信息、物流站点信息、仓储信息、库存信息、仓储间流转订单信息等<br>③ 个人终端数据：个人设备信息、会员等级/积分信息、社区互动信息、地域信息等 | 视业务形态按低危接收或直接驳回 |

### 2. 组合升降级原则
* **同级多元组不升级**：相同级别的多个字段即便组合再多，不会向上跃迁评级。
* **缺元降级**：同级数据若未满足相应的组合要求（例如只有二元组数据，缺少第三个关键字段），**强制降一级认定**。

# 二、严重漏洞 (Critical)

### 1. 业务逻辑与资金安全类
* **海量资损 / 刷钱**：黑产正在利用的能实际造成海量资损的漏洞，或能直接刷钱的漏洞。
  * **【明确不包含】**：拉新活动、云资源的后付费使用、部分无法实际套现的优惠券等。

### 2. 服务端与基础设施控制类
* **核心网络控制**：获取任意一台核心网络服务器的权限（可使用官方网络判断工具），或能直接下线生产应用。
* **网络基础设施瘫痪**：攻击网络或网络设备造成控制或瘫痪系统，使得菜鸟关键业务功能不可用或被监听。
* **海量服务器控制**：通过未授权访问后台等方式获得海量服务器的控制权限，且包含业务敏感信息。

### 3. 数据安全与越权篡改类
* **海量重要数据查询**：通过 SQL 注入或接口泄漏等方式，获取海量重要敏感信息多元组数据。
* **海量订单与身份篡改**：海量用户订单、用户身份信息等业务核心功能核心数据的无遍历限制修改、查询。
* **对象存储供应链风险**：核心敏感业务数据对象存储篡改，如能造成供应链攻击，或业务面临重大风险。
* **批量身份伪造**：交易及聊天软件场景的批量任意伪造身份并发送任意内容信息。

### 4. 账号体系与首页篡改
* **主账号任意接管**：菜鸟主账号体系的任意账号登录，或主账号体系任意撞库且证明能直接登录的问题。
* **主站首页修改**：直接能修改业务 `www` 首页关键位置信息。

### 5. 云安全与虚拟化逃逸
* **容器/沙箱逃逸**：利用普通用户的 ECS、沙箱、Docker 等权限，提升到宿主机/集群的权限。
* **数据库跨租户提权**：利用普通的数据库权限提升，获取到实例中其他用户数据库内容的权限。

# 三、高危漏洞 (High)

### 1. 业务逻辑与黑产利用
* **大量资损**：黑产已经在利用的能实际造成大量资损或潜在可造成海量资损的漏洞（不包含拉新、云资源后付费、无法套现的券）。
* **黑产升级认定**：CSRF 加购物车等中危问题若已被黑产利用，视情况升级为高危。
* **主营核心资源刷取**：主营业务收费功能的大金额无限次数免费或极低价获取（如新人优惠、试用、优惠券、虚拟物品等）。

### 2. 服务端与系统权限
* **生产服务器权限**：获取任意生产应用云上业务的服务器权限。
* **文件深度读取**：可读取到服务器上敏感文件或能进一步深度利用。
* **心脏滴血利用**：可通过类似心脏滴血漏洞随机获取到主账号体系的敏感信息，且证明可以利用信息进行账号登录或其他敏感操作。
* **核心拒绝服务**：可通过简单手段造成重要业务核心功能 DOS。
* **其他服务端危害扩大**：其他可造成进一步扩大攻击的服务端类问题。

### 3. 网络与 SSRF 类
* **进核心网络代理**：网络层 HTTP/Socks/TCP 代理可进入核心网络。
* **核心网络回显 SSRF**：可达核心网络，并可完全回显或通过图片等形式回显的 SSRF。

### 4. 数据查询、修改与存储
* **大量重要敏感数据注入/越权**：通过注入或接口泄漏等方式可获取大量重要敏感信息多元组数据（如核心功能处重要敏感数据的 SQL 注入、重要数据接口的越权等）。
* **大量订单与身份篡改**：大量用户订单、用户身份信息等业务核心功能核心数据的无遍历限制修改、查询。
* **数据存储控制**：能控制重要数据的存储设备，增删改查大量敏感信息。
* **大量后台未授权**：通过未授权访问后台等方式获得大量服务器的控制权限，且包含业务敏感信息。

### 5. 账号体系与子站缺陷
* **非主账号任意重置/接管**：非业务主账号体系的任意密码重置、任意账号登录问题。
* **子站首页篡改**：直接能修改业务子站首页关键位置信息。

### 6. 前端安全类
* **核心无交互存储 XSS**：核心功能处可影响所有用户的无交互存储 XSS，如淘宝/菜鸟商品页面、店铺页面。
* **传播型攻击**：蠕虫型 XSS、水坑攻击。
* **管理权限窃取 XSS**：影响客服、管理员并可获取到敏感数据，或可登录相应管理平台的 XSS。

### 7. 其他
* 其他可造成重要危害的问题。

---

# 四、中危漏洞 (Medium)

### 1. 业务收费逻辑缺陷
* 主营业务收费功能的大金额少量次数或小金额大量次数刷取。
* 非主营业务收费功能绕过付费（如业务上第三方应用多次免费使用、媒体资源绕过付费等）。

### 2. 服务端与系统缺陷
* **测试环境服务器控制**：获取任意测试业务的服务器权限。
* **普通敏感信息泄漏**：服务端配置文件、备份文件泄露、非核心业务数据库 SQL 注入、少量敏感数据或无重要敏感数据的 SQL 注入但无法进一步利用。
* **受限文件读取**：任意文件读取或操作部分非敏感文件且无法进一步利用。
* **非核心拒绝服务**：造成非核心应用 DOS。
* **心脏滴血**：获取到部分敏感信息但无法进一步利用。
* 其他有一定危害的服务端类问题。

### 3. 策略与验证绕过
* 手机安全锁绕过、二次验证绕过。
* 加密算法破解获取敏感信息。

### 4. 数据查询、修改与存储
* **数据查询**：通过注入及接口泄漏等方式，可获取少量重要敏感信息或大量次重要敏感信息。
* **资产数据微调**：少量商品、店铺、会员认证身份、订单、服务器、ECS、资金等核心资产信息及不涉及上述信息的修改。
* **一般存储控制**：能控制一般应用的存储，增删改查部分业务信息。
* **后台未授权**：通过未授权访问后台含少量敏感信息。

### 5. 账号类问题
* 撞库类问题能爆破出数据但无法继续利用。
* 需要较高利用条件的核心账号体系任意登录（如 6 位验证码爆破）。
* 用户量很少的业务自建账号体系任意登录。

### 6. 前端与跨域安全
* 普通存储 XSS（论坛帖子页面、分享页面等）、客户端 XSS、无自然流量页面存储 XSS、反射型 XSS。
* 执行敏感操作的 CSRF 漏洞。
* 敏感信息 JSONP 劫持、CORS 跨域信息劫持。

### 7. APP 与客户端类
* **远程利用深度控制**：通过扫码、访问 URL 等形式造成的远程 RCE，并通过反编译、解密等进一步可造成读取用户手机文件、0-Click 安装程序、获取短信记录、获取通话记录等高风险操作。

# 五、低危漏洞 (Low)

### 1. 轻微信息泄漏
* PHPinfo 泄漏、含有少量敏感信息的 SVN 信息泄漏。
* 客户端应用本地 SQL 注入（仅泄漏数据库名称、字段名、cache 缓存内容等）。
* 日志打印明文敏感信息、配置信息泄露。

### 2. 交互限制与复杂度较高漏洞
* 管理功能垂直越权（未危害核心数据）。
* Post 型 XSS、Postmessage 机制 XSS。
* 仅影响同一组织内的受限存储 XSS。

### 3. 轻微设计缺陷
* 对单个手机号的无限短信轰炸漏洞。
* URL 开放重定向跳转漏洞。
* 页面包含漏洞、CRLF 换行注入、HTML 文本注入。

### 4. 边缘越权
* 不涉及业务核心功能数据，或少量非重要敏感信息的增删改查越权问题。

---

# 六、无危害与不予收录 (Informational / Out of Scope)

> **奖励标准**：0 贡献值，0 安全币。

### 1. 不涉及安全问题的 Bug
* 产品功能缺陷、异常报错、网页乱码、样式混乱、静态文件目录遍历、应用版本兼容性等。

### 2. 无法直接利用的漏洞
* 路径信息泄漏、Self-XSS、无意义异常报错、内网 IP 地址/域名泄漏、管理后台地址泄漏、example 等默认 demo 未删除、无敏感信息的 SVN 泄漏。
* 只有固定版本小众浏览器才能触发的 XSS。
* 邮件轰炸、轮循多个手机号的短信轰炸。
* 需要预测复杂参数的 XSS / CSRF 等漏洞。

### 3. 主观猜测
* 不能直接反映漏洞存在的其他问题（包括但不仅限于纯属用户猜测）。

---

# 七、漏洞处理一般策略 (去重与排期机制)

1. **同应用大批量同类漏洞**：按正常等级确认前 3 个。若由同一问题点引起，修复一处其他自动修复的（如统一过滤函数绕过、框架层缺陷），**只确认第 1 个**。
2. **越权去重**：同一功能的越权增删改查，**只确认 1 个**；相似接口（如 `getDetail` 与 `getList`），**只确认 1 个**。
3. **同库 SQL 注入**：同一应用下同一数据库的 SQL 注入，**确认前 3 个**（第 1 个正常确认，后 2 个降一级确认）。
4. **0-Day 策略**：0-Day 类漏洞按实际影响的业务确认，**最多确认前 3 个**；无实际业务影响案例的不予关注。
5. **公共组件策略**：同一组件导致的多个业务问题（如统一二方 SDK 漏洞），确认前 3 个；若是同一漏洞源修复一处全自动修好的，只确认第 1 个。
6. **内部已知 Web 漏洞**：仍处于漏洞处理时效内的，对外按重复驳回；严重超出处理时效的，对外正常确认（已申请不修复或短期不修复除外）。
7. **内部已知 APP 漏洞**：对外一律按重复驳回。
8. **严重超期漏洞补偿**：外部上报后严重超期未处理的 Web 及 APP 漏洞，对外正常确认（申请不修除外）。
9. **内部工具对账**：内部安全工具检测到白帽提交的漏洞，在 1 个工作日内上报内部的，对外正常确认；超过 1 个工作日的，按重复驳回。
10. **社工排斥**：通过社会工程学手段获取重要账号登录系统等，不在收集范围。

# 八、漏洞降级、无效与重复场景细则

1. **交互成本降级**：除 CSRF、反射 XSS、JSONP 本身就需要交互的前端漏洞外，其他漏洞若需要受害者配合（如访问特定链接、点击特定页面按键等交互成本），**降级确认**。
2. **利用限制降级**：有较高前置限制的利用（如任意重置密码必须在极短时间内爆破 6 位验证码、仅在特定极端依赖环境下触发），**降级确认**。
3. **极小用户量降级**：影响用户量或数据量极小（新上线系统只有极少有效用户、下线旧系统只有少量有效数据等），**降级确认**。
4. **部分重复降级**：利用链中部分环节与其他报告重复的，降级确认；全部重复的按重复驳回。
5. **URL 跳转前置限制**：URL 跳转需要登录态，或必须注册固定特定域名才能跳转的，降级确认。
6. **复合利用成本过高**：利用环节极为复杂、多个漏洞无法组合成简单攻击、或必须依赖暴力破解耗费大量时间与人力成本的，降级确认。
7. **理论化与无 PoC 无效**：未提供真实成功案例仅说明理论可行的，漏洞无效；仅提供最终结果未提供完整验证 PoC 的，漏洞无效。
8. **非 Chrome 降级**：只有在非 Chrome 浏览器下才能触发的前端漏洞（XSS、JSONP 等），**最高仅定为低危**。
9. **无业务云虚机无效**：未运行实际业务的机器不在关注范围（如云上纯测试机器的 RCE 等）。
10. **防护绕过危害证明（WAF / RASP）**：
    * **WAF 场景**：在已有 WAF 防护下，SQL 注入漏洞必须提供**可手工注出当前表 1 条实际数据的证明**（禁止使用 SQLMap，须提前联系运营）；XSS 必须证明可引入并执行外部 JS。未能提供者，降级确认。
    * **RASP 场景**：在已接入 RASP 情况下，必须提供**可执行敏感系统命令的实测证明**（提前联系运营授权）。未能提供者，降级确认。

# 九、不关注的漏洞清单 (硬否决项)

1. 非核心账号体系的账号、密码暴力破解或用户名遍历。
2. 管理后台登录界面的账号、密码暴力破解。
3. 无法持续利用的短信、邮箱轰炸（如仅能通过高并发条件竞争瞬间刷发等）。
4. PDF 内嵌 XSS。
5. 通过传入超大 `PageSize`、畸形图片尺寸等导致的服务端响应超长问题。
6. 菜鸟账号的用户名遍历、固定常见弱密码的账号撞库。
