# 小米安全中心 (MiSRC) 漏洞评分标准

> **适用范围**：小米集团各业务线、MIUI/HyperOS 系统、手机/平板/电视/穿戴智能硬件、生态链 IoT 设备、海外业务。  
> **判读原则**：按业务等级（核心业务/一般业务/边缘业务）与技术危害分档，涵盖 Web 服务端与移动/智能终端全栈。零信息丢失，纯结构化 Markdown 汇编。

---

# 一、敏感数据定义与泄露量级划分

### 1. 敏感数据类别定义
* **业务类数据**：业务身份凭据、高权限 AK&SK / Token、可直接连接核心业务服务器/数据库账号密码等；收货人姓名、手机号、详细收货地址、身份证信息、购买商品记录、银行卡号等。
* **公司类数据**：员工姓名、员工身份证号、员工账号密码、员工个人电话、薪资、部门架构、联系方式、职级、绩效数据；业务经营管理数据、核心技术资产数据等。
* **用户类数据**：真实姓名、身份证号、联系方式（手机号、邮箱、社交账号）、住址、照片、银行卡号、完整交易信息（含详细购买记录、资金流水等）、医疗健康信息、账号密码等。

### 2. 敏感数据泄露量级阈值
* **巨量**：**> 100,000 条**（十万条以上）
* **大量**：**> 10,000 条**（一万条以上）
* **少量**：**> 1,000 条**（一千条以上）
* **极少量**：**< 100 条**（低危认定门槛）

# 二、Web 与服务端评分标准

| 等级 | 判定细则与影响边界 | 奖励区间 (贡献币) |
| :--- | :--- | :--- |
| **严重 (Critical)** | ① **核心权限控制**：直接获取核心系统权限，可直接危害内网的漏洞（包括但不限于命令执行、远程溢出等）<br>② **巨量核心数据**：能够获取**巨量 (>10W条)** 小米用户核心数据或商业机密合同的漏洞（包括但不限于核心 DB SQL 注入）<br>③ **支付资金逻辑**：涉及支付相关严重逻辑漏洞、能够巨量获取利益造成公司/用户损失的漏洞<br>④ **核心业务逻辑**：核心系统的严重逻辑漏洞（任意账号登录、获取巨量敏感信息越权、交易/聊天场景批量伪造身份发送信息等）<br>⑤ **账户体系接管**：危害小米账户体系的漏洞（无交互任意小米账户登录并获取详尽信息、登入小米云控制手机、用户支付等权限） | **核心业务**：600～1500<br>**一般业务**：300～500<br>**边缘业务**：80～150 |
| **高危 (High)** | ① **大量用户数据**：能够获取**大量 (>1W条)** 用户敏感信息的漏洞（包括但不限于非核心站点的 SQL 注入）<br>② **受限命令执行**：非核心业务或影响范围有限的命令执行 (RCE)<br>③ **大量获利逻辑**：个别活动、业务的逻辑漏洞（如刷积分、刷红包，确实可获取大量利益）<br>④ **源码凭据泄露**：源代码压缩包泄漏、硬编码密码等引起的公司及业务大量敏感信息泄露<br>⑤ **高权限后台突破**：弱口令或认证信息绕过进入后台，且业务中有实际权限或代码泄露，可实际操作线上业务造成较大危害<br>⑥ **多协议内网 SSRF**：可 SSRF 探测内网，支持多种协议，可探测内网服务<br>⑦ **交互式账号登录**：特定场景下或通过一定用户交互才能登录个别小米账户且具备实际用户操作权限<br>⑧ **广泛传播 XSS**：可获取核心 Cookie 等敏感信息或能造成广泛传播的存储型 XSS | **核心业务**：300～500<br>**一般业务**：100～200<br>**边缘业务**：10～30 |
| **中危 (Medium)** | ① **微量/无敏感注入**：少量或无敏感信息泄漏的 SQL 注入<br>② **无回显 SSRF**：无回显且无法证明实际危害的 SSRF 漏洞<br>③ **交互前端危害**：需交互方可影响用户的漏洞（存储型 XSS、重要敏感操作 CSRF、不受浏览器策略限制的 DOM-XSS）<br>④ **破坏性越权**：具有破坏性的越权漏洞（编辑、删除他人评论，更改功能属性等）<br>⑤ **文件包含与遍历**：文件包含、目录遍历、能查看到少量敏感信息且无法进一步利用的漏洞<br>⑥ **代码泄漏（未利用）**：GitHub 等代码平台涉及小米敏感信息，有较敏感信息但未成功利用<br>⑦ **文件上传限制危害**：文件上传只能造成钓鱼或重要业务存储 XSS 危害<br>⑧ **多步强交互漏洞**：需要强交互、多步交互（两步或以上）才能对用户产生较大影响；域名指向错误可被攻击者任意劫持<br>⑨ **受限逻辑遍历**：操作涉及用户/系统敏感信息但规模无法扩大（只能少量遍历） | **核心业务**：50～80<br>**一般业务**：10～40<br>**边缘业务**：1～5 |
| **低危 (Low)** | ① **边缘前端与交互**：特定情况下才能获取用户信息的反射型 XSS、CSRF、临时文件遍历、URL 开放跳转、短信轰炸<br>② **轻微信息泄露**：调试信息、Phpinfo、SVN 文件泄露、员工测试服务器账号密码等有一定敏感信息的机器日志文件<br>③ **难以利用隐患**：确认为漏洞但利用难度极大的问题<br>④ **应用层 DoS**：应用层缺陷导致的拒绝服务类攻击<br>⑤ **微量逻辑遍历**：逻辑漏洞但无法获取或只能获取**极少量 (<100条)** 敏感信息的情况 | **核心/一般**：5～10<br>**边缘业务**：1～5 |

# 三、移动端 / 系统 / 智能硬件评分细则

| 等级 | 判定细则与影响边界 | 奖励区间 (贡献币) |
| :--- | :--- | :--- |
| **严重 (Critical)** | ① **设备永久变砖**：绕过 Secure Boot 远程发起永久性拒绝服务，导致设备无法再使用，需刷机、双清才可恢复<br>② **内核/完整 ROOT**：获取完整 ROOT 权限（解除 SELinux、Namespace 等限制，具备完备读写执行权限）<br>③ **特权进程远程代码执行**：在系统特权进程中远程执行任意代码<br>④ **TEE 深度突破**：在 TEE（可信执行环境）中执行任意代码；未经授权访问受 TEE 保护的指纹、闪付卡、人脸等财产数据<br>⑤ **远程控制终端**：远程完全控制手机（根据利用门槛与实际危害评估）<br>⑥ **远程静默安装**：远程静默安装任意应用（用户完全无感知；通知栏有明确下载提示降为高危） | **核心业务**：2500～12000<br>**一般业务**：500～2000<br>**边缘业务**：200～500 |
| **高危 (High)** | ① **用户敏感数据窃取**：远程可获取用户照片、通讯录、通话音频等敏感信息<br>② **普通进程远程执行**：远程在普通应用进程中执行任意代码<br>③ **特权数据越界访问**：远程访问仅限于特权进程才可访问的保护数据<br>④ **本地特权提权**：本地在特权应用、TCB 或 ICE 中执行任意代码<br>⑤ **系统锁屏绕过**：系统级别的通用锁屏绕过（须在最新开发版上可稳定复现）<br>⑥ **本地持续变砖**：本地发起的持续性拒绝服务，导致设备必须刷机双清恢复<br>⑦ **沙箱数据任意读取**：远程读取受害 APP 沙箱内的任意私有数据<br>⑧ **功能越权操控**：无需交互远程开启/关闭通常需用户许可的功能；绕过设备保护功能（如“手机找回”）；绕过运营商网络制式限制<br>⑨ **本地静默安装**：本地静默安装任意应用（用户完全无感知） | **核心业务**：600～3000<br>**一般业务**：300～600<br>**边缘业务**：60～100 |
| **中危 (Medium)** | ① **远程临时 DoS**：远程发起暂时性 DoS，导致系统挂起或设备重启<br>② **接口欺骗与钓鱼**：接口逻辑漏洞造成欺骗用户、伪造钓鱼<br>③ **本地沙箱数据读取**：本地读取受害 APP 沙箱内部任意数据<br>④ **应用级锁屏绕过**：APP 级别的受限锁屏绕过<br>⑤ **交互安全设置绕过**：本地绕过安全设置修改时的交互要求<br>⑥ **本地免权获取隐私**：本地无权限获取用户身份证、手机号等敏感信息<br>⑦ **本地普通应用 RCE**：本地在普通应用上下文中执行任意代码<br>⑧ **本地静默开关功能**：本地打开或关闭需用户许可的功能<br>⑨ **证书校验缺失**：客户端未实施有效的 SSL 证书校验导致泄露用户身份凭证 | **核心业务**：150～400<br>**一般业务**：60～150<br>**边缘业务**：10～20 |
| **低危 (Low)** | ① **多次交互漏洞**：需要用户多次（大于 2 次）交互才能触发的漏洞<br>② **升级劫持**：APP 升级功能劫持类缺陷<br>③ **物理接触攻击**：需要物理接触且用户深度配合才能造成的信息安全漏洞<br>④ **非用户数据获取**：获取非用户相关的系统公开/运行信息<br>⑤ **地址栏欺骗**：移动端浏览器地址栏欺骗攻击<br>⑥ **应用级崩溃**：远程发起 DoS 仅导致单一应用崩溃重启<br>⑦ **受限进程执行**：本地在受限沙箱进程中执行任意代码<br>⑧ **轻微逻辑缺陷**：影响较小的安全设计或逻辑缺陷 | **核心业务**：30～60<br>**一般业务**：10～30<br>**边缘业务**：1～10 |

# 四、忽略与不予收录场景 (Ignore)

### 1. 代码与客户端数据保护类
* 缺少 SSL 证书绑定 (Certificate Pinning)。
* 在 TLS 保护下的 URL 或 Request Body 中传输敏感数据。
* 用户数据未加密存储在外部存储设备（有敏感信息的 APP 日志或官方声明加密除外）。
* APP 缺少代码混淆保护、APK 可以被重打包、含有已硬编码或可逆向密钥。
* 受到 APP 私有目录常规保护的正常敏感数据。
* 安卓 APP 中缺乏二进制加壳保护、设置 `allowBackup="true"`。

### 2. 低影响拒绝服务 (DoS)
* 向导出组件发送畸形 Intent 仅导致 APP 本地崩溃闪退。
* 过度申请系统资源导致的浏览器或应用崩溃。
* 用户通过手动重启应用即可解决的本地 DoS 攻击。
* 暂时性 Android Framework 自动重启。

### 3. 理论与无实证问题
* **无效 SSRF**：SSRF 漏洞无法获取内网相关服务器信息，仅能简单访问外部 DNSLog，无实际内网影响。
* **空运维组件未授权**：ZooKeeper、Memcached、Redis 等未授权访问，若无实际业务数据或无法进一步利用，予以忽略。
* **无敏感操作**：Self-XSS、无敏感操作的 CSRF、无意义的目录遍历、401 基础认证钓鱼、无敏感 logcat、纯 JS/IMG 打包文件。
* **扫描与猜测**：产品功能缺陷、网页乱码、报错、纯属猜测、无证明的扫描器结果。

### 4. 大模型与新兴风险边界
* 与大模型提示 (Prompt) 和响应内容直接相关的问题暂不收录。
* APP 在申请并获得权限后，获取权限允许范围内的数据内容属于正常功能。
* 仅在越狱/ROOT 环境下借助 Frida、Appmon 等 Hook 工具实施的运行时攻击。
* 欺骗性较低的钓鱼、利用条件极度苛刻且危害极小的问题。

# 五、特别协同机制

* **内部排查期规定**：外部披露的关联/类似漏洞，公开 3 天内属于小米内部排查期。排查期内提交的非已知漏洞予以**降级处理**，超出排查期按照正常标准定级。
* **三方组件核实**：高通、联发科、ARM 等三方底层组件漏洞，若三方已知或已排期则酌情降级/忽略；若由小米定制代码修改引入或仅影响小米，则按正常标准全额处理。
