# 京东安全应急响应中心 (JSRC) 外部威胁处理规则与漏洞评分标准 (V9.1)

> **适用范围**：京东商城、京东金融/科技、京东物流、京东健康、1号店、7fresh 及相关业务系统。  
> **判读原则**：以技术危害、利用链路完整性、受影响资产层级与业务实际影响综合定级。零信息丢失，纯结构化 Markdown 汇编。

# 二、严重漏洞 (Critical)

### 1. 系统权限与基础设施控制
* **核心系统权限获取**：直接获取核心系统权限（服务器权限、核心客户端权限），包括但不限于：远程命令执行 (RCE)、Webshell、反弹 Shell、容器逃逸、获取 root / 集群管理权限。
* **核心代码执行**：核心产品客户端的无前置条件远程任意代码执行。

### 2. 核心数据泄露
* **核心 DB 注入**：核心数据库的 SQL 注入漏洞。
* **核心数据接口暴露**：包含公司内部核心资产、海量核心用户敏感数据（身份凭据、资金账户、详细订单交易）的核心接口信息泄露。

### 3. 支付资金与账户接管
* **支付逻辑缺陷**：涉及京东支付系统、白条系统的严重逻辑缺陷（如任意金额支付、刷取真实现金或等价物）。
* **账户体系劫持**：无前置条件直接接管平台任意用户账号或重置密码。

# 三、高危漏洞 (High)

### 1. 敏感信息泄露
* 源代码压缩包泄漏、硬编码生产环境密码。
* 未授权访问敏感管理后台。
* 越权或直接获取大量用户、员工敏感信息（姓名、手机号、收货地址、身份证号等）。

### 2. 账号体系暴力破解
* 涉及京东统一账号体系的高效暴力破解漏洞、验证码风控缺陷。

### 3. 客户端权限获取
* 可远程获取客户端权限的漏洞：远程 RCE、远程缓冲区溢出、可进入内网获取数据的客户端漏洞。
* 可获取核心 Cookie 等敏感信息或能造成广泛传播的存储型 XSS。

### 4. 内网穿透 SSRF (回显型)
* **连通性实测验证**：能访问京东内网并成功回显。
* **【唯一指定测试桩】**：必须访问京东安全官方提供的验证目标：  
  `http://ssrf.jd.local/c3f3f53c12674acdc9855f47b85299f0.html`  
  *未能访问该官方桩的测试视为无效，不予计分。*

# 四、中危漏洞 (Medium)

### 1. 交互式前端漏洞
* 需受害者交互才能获取用户身份信息的漏洞：包含用户/网站敏感数据的存储型 XSS、涉及敏感操作的 CSRF。

### 2. 水平/垂直越权与逻辑缺陷
* 一般业务系统的越权行为（越权查询非敏感数据、修改非核心属性）。
* 对经济价值影响较小的业务逻辑设计缺陷与流程绕过。

### 3. 受限注入与文件读取
* 非核心业务数据库 SQL 注入漏洞、少量敏感数据或无重要敏感数据的 SQL 注入。
* 任意文件读取（不可写）或部分非敏感文件读取。

### 4. 无回显 SSRF
* 能直接访问京东内网但无回显的 SSRF 漏洞（同样须证明连通内网）。

### 5. 账号会话缺陷
* 1-Click 会话劫持（权限有限，无法完全接管账号）。
* 需复杂交互的 OAuth 绑定或登录劫持。

---

# 五、低危漏洞 (Low)

### 1. 边缘前端安全
* 只在特定情况（如特定非主流浏览器）下才能获取用户信息的反射型 XSS。
* 开放 URL 重定向跳转漏洞。

### 2. 轻微信息泄漏
* 调试信息泄露、Phpinfo 页面、SVN / Git 文件泄露、日志打印明文等。

### 3. 有限场景频控
* 对单一手机号无限制的短信轰炸。

### 4. 难以利用的隐患
* 利用条件极其苛刻但存在安全隐患的问题。

# 六、忽略与不予收录清单 (V9.1 明确规则)

> **判定标准**：以下类型提交一律忽略（0 分），若违反测试规范视情况封禁账号。

1. **违规与未授权测试**：
   * 未经授权进行内网渗透、内网扫描、提权、抓取凭据。
   * 使用扫描器等自动化工具影响业务正常运行。
   * 修复前公开漏洞细节，或修复后公开未脱敏报告。
2. **边缘资产低危免收**：
   * 边缘资产（如云鼎）不收取低危漏洞。
   * ISV 业务系统不收取低危漏洞。
3. **特定对象存储域名上传**：
   * `jcloud-oss` 域名下的正常文件上传不作为漏洞。
   * `jcloudcs.com` 域名下的正常文件上传不作为漏洞。
4. **特定逻辑与越权豁免**：
   * 电商业务中的**子账号越权主账号问题暂不收取**。
   * 无法影响他人的无意义越权。
5. **云容器环境预期 RCE**：
   * 位于云 VPC 且因功能需求**动态生成容器的代码执行 (RCE)**，属于预期业务功能，**降级或不收**。
6. **常见拒绝服务与轰炸**：
   * 邮箱轰炸漏洞、横向短信轰炸（轮循多手机号）。
   * 短链接爆破问题。
   * 基于网络层面的拒绝服务攻击 (DoS / DDoS)。
7. **合规与非技术类**：
   * 内容安全问题、模型输入输出内容安全风险。
   * 隐私合规类问题。
8. **无实证与无效扫描**：
   * 无法稳定复现、纯属猜测、无 PoC 的理论报告。

# 七、JSRC 测试规范与红线纪律

1. **SSRF 测试唯一桩**：
   * 必须使用官方提供的 URL 进行测试：  
     `http://ssrf.jd.local/c3f3f53c12674acdc9855f47b85299f0.html`  
     *严禁私自扫描内网其他 IP/端口，否则视为违规！*
2. **SQL 注入测试红线**：
   * **仅允许手工注入读取数据库名（如 `select db_name()`）**；
   * **严禁读取表内敏感数据**，否则一律不予计分并视情况追责。
3. **越权测试红线**：
   * 越权读取数据**严格限制在 5 条以内**（证明危害即可）；
   * **严禁使用线上正常用户账号测试越权增删改**，所有修改类测试必须在白帽子自己注册的测试账号之间进行。
4. **RCE 报备机制**：
   * 发现命令执行类漏洞时，应立即停止测试并向 JSRC 运营报备，经授权后才可继续。
   * 严禁反弹 Shell、内网横向、植入后门、读取业务源码。
